# 炒股系统

本文档说明股市服务、行情刷新、行为采集、交易、UI 与存档的边界。股票价格、手续费、周期、事件概率和全部玩家可见数值统一维护在 `docs/游戏机制与玩法内容.md` 第 16、17 章。

## 1. 模块边界

| 实现 | 职责 |
| --- | --- |
| `res://scripts/game/stock_market_service.gd` | 行情、价值中枢、情绪、大盘、周期、事件、证券币和行为累计的唯一数据所有者 |
| `res://scripts/ui/stock_market_panel.gd` | 查询快照、绘制列表与交易区、调度实时行情和发起交易命令 |
| `res://scripts/ui/stock_chart_control.gd` | 只读绘制选中股票的价格历史，不访问服务或存档 |
| `res://scripts/ui/securities_transfer_dialog.gd` | 输入充值或提现金额并展示预览，不直接修改资产 |
| `res://scripts/game/global_inventory.gd` | 持有股票数量、平均成本和局外星穹的唯一所有者 |

股市面板不得复制行情公式或持有可独立演化的行情副本。服务返回快照；面板提交股票 ID、数量和操作类型；服务在最终成交时重新读取实时价格并复核证券币、星穹和持仓。

## 2. 行情模型

每只股票使用三层状态：

- 当前价格：交易和折线展示使用的实时值。
- 动态价值中枢：均值回归和长期漂移的参照值。
- 初始价格：极端软边界和全局基准。

正式行情由中枢、市场情绪、玩家行为、大盘、累计周期、随机事件和均值回归共同生成。界面打开时的微行情只提供可见波动，不推进正式周期、不消费事件次数，也不重复应用玩家行为。

当前随机情绪波动统一乘 `1.25` 全局倍率。量子军备、星穹防务、骇客数字科技、前线保障、遗迹勘探的基础波动率依次为 `3%`、`2%`、`3%`、`2%`、`4.5%`，标准有效波动率依次为 `3.75%`、`2.5%`、`3.75%`、`2.5%`、`5.625%`。面板微行情使用标准波动的 `22%`，局外定时刷新使用 `50%`；震荡市和随机事件倍率在此基础上继续叠乘。

所有价格与证券币金额在服务层统一处理精度和下限。UI 可以格式化显示，但不得自行改变成交价、手续费或平均成本。

## 3. 刷新来源

| 来源 | 触发条件 | 允许影响 |
| --- | --- | --- |
| `settlement` | 正式战斗结算 | 完整行情、行为、中枢漂移、大盘、周期、事件和联动信号 |
| 局外定时刷新 | 非战斗在线累计达到间隔 | 小幅行情、在线周期与事件进度 |
| 面板微行情 | 股市面板打开期间 | 当前价、历史折线和浮动盈亏；不推进正式状态 |
| 开发者刷新 | 开发者菜单明确操作 | 按调试命令触发对应全量或小幅路径 |

任一正式或局外周期触发后，服务负责同步重置另一条进度，避免局数和在线时长在相邻帧重复触发同一状态变化。

`market_refreshed(refresh_source)` 是对外联动入口。矿场只响应明确的正式结算来源，不读取面板微行情。

## 4. 行为采集

业务模块只上报已发生的事实，不计算股票涨跌：

| 来源 | 上报事实 |
| --- | --- |
| `PlayerController` | 成功射击、武器实际耐久消耗、实际受伤和成功冲刺 |
| `EquipmentComponent` | 防具实际耐久消耗与首次损坏 |
| `LootChest` | 宝箱实际开启或击毁 |
| `GlobalInventory` | 首次战场获得、物资送回、修复包使用和失败损失 |
| `CombatHud` | 存活时间、成功撤离时的实际随身价值 |

服务把事实映射到对应股票并在正式结算时封顶、累计和清空。调用方不得传入最终涨跌比例，以免业务模块依赖股市平衡参数。

强化石的稀有品质事实统一识别高级、极品与特化；三者都计入骇客数字科技的高品质强化石指标，并同时计入遗迹勘探开发的高品质物品指标。具体单件涨幅以机制总表为准。

## 5. 随机事件

- 单股事件只影响目标股票后续的中枢方向、情绪或波动。
- 全局事件影响全部股票或大盘状态。
- 事件不在触发瞬间直接改写价格，而是作用于后续合法刷新。
- 正式结算次数与非战斗在线时长都可触发事件；面板微行情不推进事件生命周期。
- 面板只展示服务返回的事件消息和剩余状态，不自行判断事件是否结束。

事件名称、触发范围、持续次数和具体倍率见机制总表。

## 6. 交易流程

```text
面板读取实时快照
    -> 数量弹窗按余额或持仓给出当前范围
    -> 二次确认窗口持续刷新价格与金额
    -> 用户确认
    -> StockMarketService 重新读取价格并校验
    -> GlobalInventory 原子更新持仓或星穹
    -> 服务更新证券币并立即持久化相关资产
    -> 面板响应信号刷新
```

- 买卖数量必须是正整数，证券币和价格保留服务规定的小数精度。
- 数量窗口与二次确认不会暂停微行情，也不锁定价格；成交使用最终确认瞬间的服务价格。
- 涨价导致余额不足时，数量上限和确认状态同步收紧；服务层仍执行最后一次防御性校验。
- 多次买入由服务按实际含费支出更新平均成本；卖出不改变剩余股票的单位成本。
- 充值与提现是星穹和证券币之间的跨服务交易，必须同时验证两边余额并立即保存。

## 7. UI 约定

- 股票列表、行情详情和交易摘要使用同一份快照，选中项变化时统一刷新。
- `StockChartControl` 只接收价格历史数组和显示配置，不读取股票 ID 或服务单例。
- 数量选择复用 `SellQuantityDialog`，最终确认复用 `CommonConfirmationDialog`，证券币转换复用 `SecuritiesTransferDialog`。
- 二次确认窗口在微行情期间保持稳定尺寸，更新正文和按钮状态时不重建窗口。
- 涨跌、收益、费用和风险使用语义颜色；普通控件样式遵守 `docs/ui_style.md`。
- 关闭面板后停止微行情，并保存最终行情快照。

## 8. 持久化

| 文件 | 所有者 | 保存内容 |
| --- | --- | --- |
| `user://stock_market_state.json` | `StockMarketService` | 行情、中枢、历史、大盘、周期、事件、在线进度、证券币和行为累计 |
| `user://global_inventory.json` | `GlobalInventory` | 股票数量、平均成本和局外星穹 |

- 存档版本常量只标识当前写入结构；项目尚未发布正式版本，股市和持仓不再执行历史版本迁移。
- 当前结构缺失证券币或持仓字段时使用 0 与空持仓默认值，不从局外星穹自动推导资产，也不缩放旧在线进度。
- 每秒微行情只更新内存；成交、充值和提现立即保存，面板关闭或程序退出时保存最终行情。
- 正式战斗开始后服务暂停自身逐帧处理，在线周期、事件和面板微行情都不推进；战斗结算仍由 `run_state_changed` 信号触发，并在结算完成后恢复局外在线计时。
- 兼容接口可以继续服务旧调用方，但新代码必须使用证券币交易路径。

## 9. 调试与扩展

- 主菜单输入 `LISBAM` 后，开发者菜单可触发全量刷新、小幅刷新、随机事件、大盘切换和清空持仓。
- 新增股票时必须提供稳定 ID、初始价、展示信息和行为映射，并同步机制总表；正式版本发布前不维护旧存档迁移。
- 新增刷新来源时必须明确它是否推进中枢、大盘、周期、事件、行为和矿场联动，禁止复用含义模糊的布尔参数。
- 新增行为采集时只暴露事实接口，保持战斗、库存和 UI 对定价公式无感知。
