# 游戏内容自动发现与手动创建

本文档是项目内手动创建武器、装备、道具、怪物、角色、装备套装和角色扩展包的长期维护入口。`ContentCatalog` 在项目启动时递归扫描约定目录，各业务系统从同一个目录服务查询内容，不再要求开发者把每个新文件重复写入商店、掉落、怪物生成、开发者发放和角色列表的硬编码清单。

玩法规则与当前默认数值仍以 `docs/游戏机制与玩法内容.md` 为唯一权威快照；本文只规定内容文件的创建方式、自动接入范围和验证要求。

## 1. 自动扫描目录

| 内容类型 | 放置目录 | 文件类型 | 必须唯一的稳定 ID | 自动接入范围 |
| --- | --- | --- | --- | --- |
| 武器 | `res://data/weapons/` | `.tres`、`.res` | `weapon_id` | 商店武器池、怪物武器掉落池、宝箱武器池、开发者全部武器发放、库存存档恢复 |
| 装备 | `res://data/equipment/` | `.tres`、`.res` | `equipment_id` | 商店装备池、怪物装备掉落池、宝箱装备池、开发者全部装备发放、库存存档恢复 |
| 道具 | `res://data/items/` | `.tres`、`.res` | `item_id` | 商店道具池、开发者对应道具发放、库存存档恢复；`repair_kit` 还会进入怪物与宝箱修复包池 |
| 怪物 | `res://scenes/enemies/` | `.tscn`、`.scn` | 无独立 ID，资源路径必须唯一 | 正式战斗与训练场随机怪物生成池 |
| 角色 | `res://data/characters/` | `.tres`、`.res` | `character_id` | 独立角色选择列表、会话选择、战斗基础属性、战斗 HUD 名称、训练场角色切换列表 |
| 扩展包 | `res://data/content_packs/` | `.tres`、`.res` | `pack_id` | 把所属角色解锁状态映射到武器、装备、道具和怪物四类内容池 |

以上目录允许建立任意层级的子目录，扫描会递归处理。文件按完整资源路径稳定排序；相同稳定 ID 的重复资源只会注册排序靠前的一份，因此复制模板后必须修改 ID。`EquipmentSetData` 放在 `res://data/equipment_sets/` 并由装备显式引用，不作为独立可掉落内容扫描。

## 2. 推荐创建流程

1. 在对应目录复制最接近目标的现有 `.tres` 或 `.tscn` 模板。
2. 修改文件名，并为武器、装备、道具、角色、套装或扩展包填写新的唯一英文 ID；ID 建议只使用小写英文字母、数字和下划线。
3. 修改显示名称、说明和数值。怪物场景应保留现有怪物节点协议、死亡信号、阵营碰撞层和 AI 组件结构，再按需要替换脚本或参数。
4. 返回 Godot 编辑器等待外部文件导入完成；若游戏正在运行，停止并重新启动。内容目录在项目启动时建立，不在单次运行中持续轮询磁盘。
5. 按本页的接入范围验证内容。商店已有库存不会被强制覆盖，新内容从下一次手动或自动刷新开始参与抽取；怪物和掉落池从下一次进入战斗开始生效。

创建角色专属内容时还必须完成以下步骤：

1. 先在各标准扫描目录创建并验证武器、装备、道具和怪物，建议使用以角色 ID 命名的子目录组织专属资源。
2. 复制 `res://data/content_packs/stelle.tres`，修改唯一 `pack_id`、显示名称和 `character_id`，再把四类专属资源加入对应数组。同一角色只配置一个扩展包，同一路径只归属一个扩展包。
3. 在角色 `CharacterData` 中设置 `unlocked_by_default`。默认 `false` 表示新角色及其扩展包保持锁定；设置为 `true` 后旧存档和新存档都会自动补入解锁列表。
4. 角色解锁流程只调用 `SessionState.unlock_character(character_id)`；该接口永久保存角色 ID，并同步开放清单内全部内容，不允许各业务系统分别维护解锁布尔值。
5. 已解锁扩展包会立即进入目录查询；商店保留当前商品到下一次正常刷新，战斗怪物与掉落池从下一次进入战斗开始使用新清单。

## 3. 类型与兼容规则

- 武器资源必须使用 `WeaponData` 或兼容脚本，`item_kind` 必须为 `weapon`，`weapon_id` 不得为空。
- 武器基础经济与攻击节奏字段统一使用 `value`、`energy_consumption` 和 `cooldown`，分别对应玩家物品价值、单次攻击能耗和攻击冷却；新资源不得继续声明旧 `sell_price`、`energy_cost`、`ranged_cooldown` 或 `melee_cooldown`。
- 武器攻击范围统一填写 `attack_distance`，新资源不得继续声明旧 `bullet_range`。远程武器以该值限制弹体最大飞行距离；近战武器以该值定义攻击方向最远判定端到玩家本体的距离，组件会按场景命中框的原近端与高度自动重算宽度、中心和视觉区域。该属性属于远近战通用强化属性。
- 散射、穿透、连击、后坐力和前坐力都使用显式持有开关。后坐力填写 `has_recoil + recoil_force`，前坐力填写 `has_front_recoil + front_recoil_force`；坐力数值单位为单次无碰撞理论位移像素，1 点对应 1 像素。两者互斥，一把武器至多启用其中一种，未启用的坐力数值不显示、不生效且不能强化。
- 武器冲击力填写 `impact_force`，单位同样为目标单次无碰撞理论位移像素，1 点对应无韧性目标的 1 像素；命中怪物时先按目标韧性减少理论位移，再使用目标自身的击退衰减换算初速度。
- 装备资源必须使用 `EquipmentData` 或兼容脚本，`item_kind` 必须为 `equipment`，`equipment_id` 不得为空。
- 套装装备通过 `equipment_set` 引用同一份 `EquipmentSetData`。`set_id` 必须稳定唯一；两件与四件门槛、显示原文、属性加成和特殊效果数值只写在套装资源中，不得复制到每件装备或 UI 脚本。
- 套装属性字典使用装备聚合的统一属性名，数值是直接加到有效装备结果的点数或比例。当前支持的属性效果必须已经存在于 `EquipmentComponent` 属性表；世界特殊效果由 `EquipmentSetComponent` 提供独立接口，不能由装备资源直接访问宝箱或关卡。
- 道具资源必须声明非空 `item_kind` 与 `item_id`，且 `item_kind` 不能为 `weapon` 或 `equipment`。合法道具会自动进入商店、宝箱和怪物掉落池；复制现有修复包并保持 `repair_kit` 类型还可完整复用堆叠与修复行为。
- 新的道具类型可以被内容目录、商店和存档路径识别，但如果它引入新的使用行为、卡片字段、筛选类别或堆叠规则，仍需实现对应的独立数据组件与业务组件；自动发现只负责注册，不会猜测未知玩法。
- 怪物目录中的场景必须能够加载为 `PackedScene`。复制当前的 `res://scenes/enemies/stelle/voidranger_reaver.tscn` 或 `res://scenes/enemies/stelle/voidranger_eliminator.tscn` 可以分别复用近战、远程生成协议，并通过默认 1.0 的 `drop_multiplier` 调整该怪物全部掉落概率；完全不同的根节点或脚本必须自行实现 GameWorld、MonsterSimulationManager 和死亡掉落所需接口，未声明掉落倍率时按 1.0 处理。
- 角色资源必须使用 `CharacterData` 或提供兼容的 `character_id` 与 `to_profile()`；基础属性在进入战斗和训练场切换角色时应用。`passive_skills` 可引用多个 `PassiveSkillData` 兼容资源并全部生效，`active_skills` 按顺序装入当前三个主动槽；旧 `passive` 与 `active` 字符串只作为未迁移档案的详情兜底。技能资源、行为接口、目标组和验证步骤见 `docs/skill_system.md`。
- 角色 `move_speed` 使用属性点而非直接像素速度，运行时按 `1 点 = 3 像素/秒` 换算；例如填写 `100` 等效旧规则的 `300` 速度，装备移速比例继续作用于属性点。
- 扩展包资源必须使用 `ContentPackData` 或提供兼容的 `pack_id`、`character_id` 与四类路径查询接口。所属角色必须已经由角色目录注册；空 ID、未知角色、重复扩展包 ID、同角色第二份清单和重复内容归属不会获得额外注册权重。
- 未列入任何扩展包清单的合法资源属于基础内容并始终可用；列入清单的资源只有在所属角色已解锁时才会由武器、装备、道具和怪物复数查询接口返回。按稳定 ID 进行的单项路径查询仍可恢复玩家已经持有的旧物品。

## 4. 生效时机与发布边界

- `ContentCatalog` 是 `project.godot` 中的自动加载服务，每次项目启动时扫描一次。开发期间外部复制完成后，等待 Godot 导入并重新运行项目即可生效。
- `ContentCatalog` 保留全部合法注册项，并在武器、装备、道具和怪物复数查询时按 `SessionState` 的角色解锁状态过滤扩展包内容。角色解锁本质上是永久解锁其唯一扩展包，不存在单独解锁某把武器或某只怪物的分支。
- 星、穹、银狼的角色资源均设置为开局默认解锁。当前只实现 `res://data/content_packs/stelle.tres` 的“星”内容清单；穹与银狼角色及其现有数值保持不变，对应专属内容清单待实际制作时新增。
- 当前实际内容池只保留“星”清单中的 2 把武器、4 件开拓者套装、3 种修复包和 2 种虚卒怪物；没有归属清单的旧武器、旧基础防具与旧怪物场景已经移除。后续新增内容必须先明确基础内容或角色扩展包归属，再按清单接入。
- 商店服务会先按扩展包状态过滤旧检查器路径，再合并自动目录，保持旧场景和旧存档兼容；相同资源路径不会获得重复抽取权重。角色解锁后新增路径从下一次正常商品刷新参与抽取。
- 战斗世界会先过滤场景原有检查器怪物与掉落池，再合并自动怪物、武器、装备和道具池；未归入扩展包的旧配置继续作为隔离测试兜底，已归入扩展包的旧路径不能绕过角色锁。
- 开发者全量发放同样只枚举当前可用的复数内容路径；稳定 ID 单项查询不受过滤，只用于存档恢复玩家已经持有的物品。
- 库存保存资源稳定 ID 和资源路径。只要文件路径或稳定 ID 至少一个仍可解析，已有实例即可恢复；发布后不应随意同时修改两者。
- Godot 导出的正式版本通常把 `res://` 内容打包进 PCK。把新文件复制到已导出游戏安装目录不会自动变成 MOD；若未来需要玩家运行时 MOD，应另建 `user://` 内容包加载、签名校验和兼容协议，不能复用本开发目录扫描规则冒充热更新。

## 5. 验证清单

- 重新启动项目后，Godot 输出中没有资源加载、脚本解析或重复 ID 错误。
- 武器、装备和道具能在下一轮商店刷新中参与对应分类抽取；开发者菜单的“全部”发放能覆盖新增模板。
- 武器和修复包在正式战斗掉落或宝箱池中可被选中，拾取后能保存并在重启后恢复。
- 怪物能被虚拟人口管理器创建、唤醒、击杀和注销，死亡信号只结算一次。
- 角色出现在独立角色页与训练场切换列表，确认后名称、生命、能量、攻击、防御和移动速度与资源一致。
- 角色详情能逐项展示全部主动与被动资源；进入战斗后被动全部创建，主动按前三项映射到技能一、二、三，空槽不产生行为。
- 默认解锁角色启动后出现在 `SessionState.get_character_ids()`；锁定角色不会进入选择列表。调用 `unlock_character()` 后角色与其扩展包同时可用，重启后仍保持解锁。
- 扩展包未解锁时，清单内四类路径均不进入复数内容池；解锁后武器、装备、道具和怪物路径全部出现，基础内容在两种状态下都不受影响。
- 套装分别验证 0、1、2、3、4 件以及损坏部件：达到 2/4 件时对应详情变绿并生效，未达到时为灰色，损坏件不计数。
- 无效类型、空 ID 和错误目录资源不会进入对应业务池；重复 ID 必须修改后再验收。
