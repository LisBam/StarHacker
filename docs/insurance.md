# 骇入保险

本文档说明骇入保险系统的服务职责、保单生命周期、理赔口径与股市联动边界。玩家可见数值以《游戏机制与玩法内容》为准。

## 1. 系统定位

- 骇入保险是撤离玩法的风险对冲工具：局外投保下一局正式骇入，死亡时按实际丢失价值的固定比例赔付星穹。
- 保险与第六只股票“星海互助保险”双向联动：保费与安全撤离推高股价，理赔压低股价。
- 主动逃跑与主动退出属于条款免责范围；训练场与联机大厅不消耗保单（只有正式对局边界触发结算）。

## 2. 服务与职责

| 部分 | 实现 | 职责 |
| --- | --- | --- |
| 保险服务 | `res://scripts/game/insurance_service.gd`（AutoLoad `InsuranceService`） | 维护保单、随身价值统计、死亡理赔、账户统计、记录与股票行为累计 |
| 保险面板 | `res://scripts/ui/insurance_panel.gd` | 展示保单卡/投保报价卡、账户统计与最近 30 条记录；投保走二次确认 |
| 主菜单入口 | `main_menu.gd` 底部“金融 ▲”展开分类中的“保险”按钮与大厅 `insurance` 动作 | 动态创建遮罩与面板 |

## 3. 保单生命周期

1. 投保（仅局外）：投保基准 = 当前背包与七个装备槽（两远程、近战、四防具）物品的有效价值合计，逐件读取 `get_effective_value()`。保费 = `max(1, ceil(基准 × 费率))`，基础费率 12%，精算办公室每级 -0.5 个百分点（最低钳制 1%）。同一时间最多一份保单，投保后不可退保。
2. 结算：监听 `GlobalInventory.run_state_changed`，在正式对局从激活转为结束的边界消耗保单：
   - `result == "success"`：计安全撤离 1 次（正向股票影响），不赔付。
   - `title == "角色死亡"`：赔付 = `floor(min(实际丢失价值, 投保基准) × 80%)`，经 `adjust_coins` 到账并广播 `claim_paid`（横幅“【保险理赔】”）。丢失价值逐条按 `lost_entries` 的资源有效价值 × 数量累计。
   - 其他失败标题（“逃跑”“主动退出游戏”）：保单消耗、不赔付。
3. 赔付比例在投保瞬间锁定进保单（`policy_claim_ratio`），后续调参不影响已生效保单。

## 4. 股市联动（关键时序）

- 保险服务把保费、赔付、安全撤离累计进待结算池；`StockMarketService._calculate_behavior_impacts()` 在每次正式结算调用 `consume_market_impact()` 一次性取走并清零。
- 影响公式（正式结算时计算，整体 ±2% 封顶）：`floor(保费/100)×0.3% + 安全撤离次数×0.4% − floor(赔付/200)×0.5%`。
- **AutoLoad 顺序契约**：`InsuranceService` 必须注册在 `StockMarketService` 之前。两者都监听 `run_state_changed`，Godot 按连接顺序派发信号，先注册者先连接，保证“理赔入池 → 股市结算取池”的顺序。调整 `project.godot` 顺序时必须保持该约束。

## 5. 持久化

- 独立写入 `user://insurance_state.json`，版本 1；保存保单字段、待结算累计、四项账户统计与最近 30 条记录。
- 保费与赔付走 `_flush_linked_saves()` 与星穹存档同路径落盘；结算发生在对局结束后（局外），不需要战斗挂起机制。
- 读档时保单基准价值非法则直接作废保单，不发放赔付。
- 文件已加入存档白名单，随导出、导入与删除统一处理。

## 6. 扩展注意

- 免责判定依赖失败结算标题常量 `DEATH_OUTCOME_TITLE = "角色死亡"`，与 `CombatHud._show_failure_settlement` 传入的死亡原因保持一致；修改死亡文案必须同步该常量。
- 新增赔付档位（如高级保单）时应把费率与赔付比例都写入保单快照，维持“签订时锁定”的口径。
