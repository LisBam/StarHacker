# 炒股系统

本文档说明股市服务、行情刷新、行为采集、交易、UI 与存档的边界。股票价格、手续费、周期、事件概率和全部玩家可见数值统一维护在 `docs/游戏机制与玩法内容.md` 第 16、17 章。

## 1. 模块边界

| 实现 | 职责 |
| --- | --- |
| `res://scripts/game/stock_market_service.gd` | 行情、价值中枢、情绪、大盘、周期、事件、证券币、杠杆合约和行为累计的唯一数据所有者 |
| `res://scripts/ui/stock_market_panel.gd` | 查询快照、绘制列表与交易区、调度实时行情和发起交易命令 |
| `res://scripts/ui/stock_chart_control.gd` | 只读绘制选中股票的价格历史与宿主整理后的通用价格标记，并处理图内长按读价；不访问服务、仓位或存档 |
| `res://scripts/ui/securities_transfer_dialog.gd` | 输入充值或提现金额并展示预览，不直接修改资产 |
| `res://scripts/ui/leverage_position_dialog.gd` | 输入杠杆方向、倍数与整数保证金并展示费用与强平价预览，不直接修改资产；加仓模式锁定方向与倍数，只输入追加保证金 |
| `res://scripts/ui/stock_stop_order_dialog.gd` | 选择止盈止损目标类型（现货 / 杠杆）、输入目标价并做本地方向预览，不读取行情或存档；最终档案由服务原子校验写入 |
| `res://scripts/ui/stock_record_list_dialog.gd` | 只读滚动展示交易历史记录与通知中心的富文本行，不访问服务或存档 |
| `res://scripts/game/global_inventory.gd` | 持有股票数量、平均成本和局外星穹的唯一所有者 |
| `res://scripts/game/banner_notification_service.gd` | 全局横幅通知 AutoLoad；订阅股市强平信号并在屏幕顶端提醒，股市服务不反向依赖它 |

股市是金融成长顺序的第四项，玩家生涯累计获得星穹达到 10000 后永久开放。门槛由 `FinanceUnlockRules` 统一维护，主菜单未解锁入口显示纯黑禁用状态；解锁只控制玩家进入面板的资格，不暂停常驻行情服务的合法后台状态。

股市面板不得复制行情公式或持有可独立演化的行情副本。服务返回快照；面板提交股票 ID、数量和操作类型；服务在最终成交时重新读取实时价格并复核证券币、星穹和持仓。

面板的每秒行情刷新走服务的轻量只读接口 `get_stock_price()` 与 `get_stock_change_ratio()`，只有首次打开、切换选中股票、正式行情刷新与事件触发才读取完整深拷贝快照；行情、余额、持仓四路信号在面板侧合并为同帧一次统一刷新，单次交易不再触发多次全量重建。

## 2. 行情模型

每只股票使用三层状态：

- 当前价格：交易和折线展示使用的实时值。
- 动态价值中枢：均值回归和长期漂移的参照值。
- 初始价格：极端软边界和全局基准。

正式行情由中枢、市场情绪、玩家行为、大盘、累计周期、随机事件和均值回归共同生成。界面打开时的微行情只提供可见波动，不推进正式周期、不消费事件次数，也不重复应用玩家行为。

当前随机情绪波动统一乘 `1.25` 全局倍率。量子军备、星穹防务、骇客数字科技、前线保障、遗迹勘探、星海互助保险的基础波动率依次为 `3%`、`2%`、`3%`、`2%`、`4.5%`、`2.5%`，标准有效波动率依次为 `3.75%`、`2.5%`、`3.75%`、`2.5%`、`5.625%`、`3.125%`。面板微行情使用标准波动的 `22%`，局外定时刷新使用 `50%`；震荡市和随机事件倍率在此基础上继续叠乘。

第六只股票“星海互助保险”（`astral_insurance`，初始价 80.00）随骇入保险系统加入（存档版本 7）：`STOCK_IDS` 顺序末位追加，UI 列表、杠杆合约、事件目录与存档循环自动覆盖；旧存档缺失该股票时按初始价与默认字段初始化，不执行历史迁移。

所有价格与证券币金额在服务层统一处理精度和下限。UI 可以格式化显示，但不得自行改变成交价、手续费或平均成本。

## 3. 刷新来源

| 来源 | 触发条件 | 允许影响 |
| --- | --- | --- |
| `settlement` | 正式战斗结算 | 完整行情、行为、中枢漂移、大盘、周期、事件和联动信号 |
| 局外定时刷新 | 非战斗在线累计达到间隔 | 小幅行情、在线周期与事件进度 |
| 面板微行情 | 股市面板打开期间 | 当前价、历史折线和浮动盈亏；不推进正式状态 |
| 开发者刷新 | 开发者菜单明确操作 | 按调试命令触发对应全量或小幅路径 |

任一正式或局外周期触发后，服务负责同步重置另一条进度，避免局数和在线时长在相邻帧重复触发同一状态变化。

首次战斗引导的库存结果为 `tutorial_success` 且携带 `progression_eligible = false`。股市在对局活动状态结束时清空本局临时行为但不执行 `settlement` 刷新，因此引导击杀、开箱、存活和保留战利品都不会推动行情、周期或事件倒数。

`market_refreshed(refresh_source)` 是对外联动入口。矿场只响应明确的正式结算来源，不读取面板微行情。

## 4. 行为采集

业务模块只上报已发生的事实，不计算股票涨跌：

| 来源 | 上报事实 |
| --- | --- |
| `PlayerController` | 成功射击、武器实际耐久消耗、实际受伤和成功冲刺 |
| `EquipmentComponent` | 防具实际耐久消耗与首次损坏 |
| `LootChest` | 宝箱实际开启或击毁 |
| `GlobalInventory` | 首次战场获得、物资送回、修复包使用和失败损失 |
| `CombatHud` | 存活时间、成功撤离时的实际随身价值 |
| `InsuranceService` | 保费、理赔与投保安全撤离的累计值；不走 `record_run_metric`，由服务自行入池并在正式结算被 `consume_market_impact()` 一次性取走 |

保险行为的取用发生在 `_calculate_behavior_impacts()` 内：股市服务经 `get_node_or_null("InsuranceService")` 防御式查询，保险服务缺失时该股票按零行为影响运行。`InsuranceService` 在 AutoLoad 中注册于股市服务之前，保证对局结束时理赔先入池、股市正式结算后取池。

银行贷款违约级联提供系统级抵扣接口 `deduct_securities(amount, reason) -> float`：按可用余额直接扣除证券币、写入 `bank_deduct` 类型交易记录并立即保存，不收提现手续费；该接口只允许银行级联等系统流程调用。

服务把事实映射到对应股票并在正式结算时封顶、累计和清空。调用方不得传入最终涨跌比例，以免业务模块依赖股市平衡参数。

强化石的稀有品质事实统一识别高级、极品与特化；三者都计入骇客数字科技的高品质强化石指标，并同时计入遗迹勘探开发的高品质物品指标。具体单件涨幅以机制总表为准。

## 5. 随机事件

- 单股事件只影响目标股票后续的中枢方向、情绪或波动。
- 全局事件影响全部股票或大盘状态。
- 事件不在触发瞬间直接改写价格，而是作用于后续合法刷新。
- 正式结算次数与非战斗在线时长都可触发事件；面板微行情不推进事件生命周期。
- 面板只展示服务返回的事件消息和剩余状态，不自行判断事件是否结束。

事件名称、触发范围、持续次数和具体倍率见机制总表。

## 6. 交易流程

```text
面板读取实时快照
    -> 数量弹窗按余额或持仓给出当前范围
    -> 二次确认窗口持续刷新价格与金额
    -> 用户确认
    -> StockMarketService 重新读取价格并校验
    -> GlobalInventory 原子更新持仓或星穹
    -> 服务更新证券币并立即持久化相关资产
    -> 面板响应信号刷新
```

- 买卖数量必须是正整数，证券币和价格保留服务规定的小数精度。
- 数量窗口与二次确认不会暂停微行情，也不锁定价格；成交使用最终确认瞬间的服务价格。
- 涨价导致余额不足时，数量上限和确认状态同步收紧；服务层仍执行最后一次防御性校验。
- 多次买入由服务按实际含费支出更新平均成本；卖出不改变剩余股票的单位成本。
- 卖出成功提示附带本次已实现盈亏，按实际到手所得减去含费加权成本折算，仅用于展示。
- 充值与提现是星穹和证券币之间的跨服务交易，必须同时验证两边余额并立即保存。
- 交易区常驻展示证券总资产；口径为证券币余额加现货实时市值加杠杆实时净值，由服务统一计算。

## 6.1 杠杆合约

杠杆合约是纯证券币结算的差价合约，完全由 `StockMarketService` 持有和持久化，不写入 `GlobalInventory` 的现货持仓结构：

```text
面板点击杠杆开仓
    -> LeveragePositionDialog 选择方向（做多 / 做空）、倍数（2× 至 999× 共 8 档）与整数保证金
    -> 弹窗实时预览名义本金、手续费、总花费与预计强平价
    -> 用户确认
    -> StockMarketService 重新读取实时价格并复核余额与仓位唯一性
    -> 扣除保证金与开仓手续费，记录开仓价并立即持久化
```

- 每只股票最多同时持有一个杠杆仓位；重复开仓必须先平掉现有仓位。
- 名义本金 = 保证金 × 倍数，开仓后固定；浮动盈亏 = 方向 × 价格变化率 × 名义本金。
- 倍数目录由服务常量统一维护；手续费与强平变化率都按名义本金和倍数自然缩放，新增倍率不需要任何额外分支。
- 净值 = 保证金 + 浮动盈亏，最低为 0；爆仓不产生负债。
- 任意来源的行情刷新（含面板微行情）后服务立即检查强平条件；浮亏达到保证金乘强平亏损线时强制平仓，返还净值扣除平仓手续费后的余额并广播 `leverage_position_closed`。
- 主动平仓与强制平仓共用同一结算路径，保证费用与净值公式一致；平仓确认窗口正文随每秒行情持续刷新，仓位被强平后确认按钮立即禁用。
- 开仓弹窗不读取任何服务；宿主传入实时价格、可用余额、费率与强平亏损线，弹窗只做本地预览，最终成交由服务原子校验。
- 已有仓位的股票支持加仓：交易区同一入口按钮自动切换为“杠杆加仓”，弹窗锁定现有方向与倍数，只输入整数追加保证金。服务按浮动盈亏守恒合并仓位——追加部分以确认瞬间实时价入场，新开仓均价由 `方向 × (现价 ÷ 新均价 - 1) × 新名义本金 = 原浮动盈亏` 反解，加仓前后浮动盈亏不变；追加名义本金按开仓同一费率收取手续费。
- 加仓弹窗打开期间仓位被强制平仓时，面板立即关闭弹窗并清理挂起状态；服务侧报价与执行都会再次校验仓位存在性。
- 具体倍数、费率、最低保证金、最低追加保证金与强平线数值见机制总表第 16.12 节。

## 6.2 止盈止损

止盈止损档案由 `StockMarketService` 独占持有和持久化（存档版本 8 的 `stop_orders` 字段），每只股票的现货与杠杆各最多一份：

```text
标题栏“止盈止损”按钮
    -> StockStopOrderDialog 选择目标类型（现货持仓 / 杠杆仓位）并输入止盈价与止损价
    -> 弹窗按当前价与仓位方向做本地方向预览（做空整体翻转）
    -> 保存设置 / 清除设置
    -> StockMarketService 按确认瞬间实时价与持仓重新校验后写档并立即持久化
```

- 触发检查 `_check_stop_orders()` 挂在 `refresh_market()` 内、`_check_leverage_liquidations()` 之后：任意刷新来源改价后立即判定，强平优先于止盈止损。
- 现货触发复用 `request_sell()` 全量卖出，成交价、手续费、交易记录与均价结算与手动卖出完全一致；杠杆触发走 `_close_leverage_position()` 统一结算路径（动作标签“止盈平仓 / 止损平仓”）。
- 触发后档案一次性消耗：写入通知中心（前缀“止盈止损通知：”）并广播 `stop_order_triggered(stock_id, message)`；横幅通知服务订阅该信号播放“【止盈止损】”横幅，服务不反向依赖横幅与面板。
- 档案生命周期清理：手动清仓（`request_sell` 持股归零）、任何路径的杠杆平仓与开发者清空持仓都会静默移除对应档案并广播 `stop_orders_changed`；读档时校验价格字段，持仓已不存在的档案在下一次刷新兜底清理。
- 面板入口为标题栏“止盈止损”按钮（“通知”左侧，90×36），不占用交易区布局行、不改变面板尺寸；无现货且无杠杆时禁用，悬停提示展示当前股票已生效目标价。弹窗打开期间随每秒行情刷新价格与方向校验，目标持仓消失（清仓或被强平）时禁用保存。
- 面板把当前股票现货与杠杆档案整理为只含 `price`、`label`、`type` 的通用价格标记后传给折线图；图表不读取服务，也不判断做多、做空或触发方向。有效止盈价绘制绿色虚线，有效止损价绘制红色虚线，标签明确区分“现货 / 杠杆”和“止盈 / 止损”。
- 折线图纵轴同时覆盖价格历史与全部有效目标价；存在目标线时在合并价格跨度上下各增加 6% 留白，确保区间外目标仍完整可见。同价的多份档案交替把标签放在左右两侧，降低现货与杠杆标签互相遮挡。
- 玩家在折线图内部绘图区按住鼠标左键 0.35 秒后进入读价状态；按住移动会持续显示鼠标所在横行对应的两位小数价格，拖出绘图区时限制为最近边界价，松开后立即隐藏。短点击、右键和从图表边框或留白开始的按下不会触发读价。
- 图表交互与视觉默认参数由 `StockChartControl` 顶部导出：目标线宽 1.5 像素、虚线段长 7 像素、价格标签字号 13 像素、标签内边距 5×2 像素、边缘距离 4 像素、读价线宽 1.5 像素；均只影响展示，不改变挂单价格、触发判断或成交结果。
- 具体方向规则与全部玩家可见数值见机制总表第 16.14 节。

## 6.3 交易历史与通知中心

- `StockMarketService` 是交易历史记录与通知记录的唯一所有者；两条列表随股市状态持久化，索引 0 恒为最新记录。
- 交易记录覆盖现货买入、现货卖出、杠杆开仓、杠杆加仓、主动平仓、强制平仓、证券币充值与提现；每条包含 Unix 时间、本地格式化时间文本、类型标识与说明文本，上限 80 条，超出丢弃最旧。
- 通知记录当前只写入强制平仓事件，上限 50 条；记录在结算路径内与仓位状态同一次保存落盘。
- 面板底部“历史记录”按钮位于“全部持仓”标题右侧的同一标题行，与标题栏“通知”按钮（关闭左侧）复用同一 `StockRecordListDialog`；窗口打开期间收到 `trade_records_changed` / `notification_records_changed` 信号时原位更新文本，不重建窗口。
- 强制平仓额外广播 `leverage_position_liquidated(stock_id, message)`；横幅通知服务订阅该信号在屏幕顶端提醒，股市服务与面板都不依赖横幅实现。

## 7. UI 约定

- 股票列表、行情详情和交易摘要使用同一份快照，选中项变化时统一刷新。
- `StockChartControl` 只接收价格历史数组和显示配置，不读取股票 ID 或服务单例；服务侧历史上限为 90 个采样。
- 数量选择复用 `SellQuantityDialog`，最终确认复用 `CommonConfirmationDialog`，证券币转换复用 `SecuritiesTransferDialog`，杠杆开仓与加仓使用专用 `LeveragePositionDialog`，止盈止损使用专用 `StockStopOrderDialog`（430×330，标题栏“止盈止损”按钮打开），交易历史与通知中心复用 `StockRecordListDialog`（560×420，强平行红色、通知行琥珀色、时间前缀灰色）。
- 底部“全部持仓”区按稳定股票顺序先排现货卡片再排杠杆卡片，两类卡片都长期复用并只在数量或仓位跨越零边界时切换可见性；现货与杠杆都为空时才显示空状态提示。
- 二次确认窗口在微行情期间保持稳定尺寸，更新正文和按钮状态时不重建窗口。
- 涨跌、收益、费用和风险使用语义颜色；普通控件样式遵守 `docs/ui_style.md`。
- 关闭面板后停止微行情，并保存最终行情快照。

## 8. 持久化

| 文件 | 所有者 | 保存内容 |
| --- | --- | --- |
| `user://stock_market_state.json` | `StockMarketService` | 行情、中枢、历史、大盘、周期、事件、在线进度、证券币、杠杆仓位、止盈止损档案、交易历史记录、通知记录和行为累计 |
| `user://global_inventory.json` | `GlobalInventory` | 股票数量、平均成本和局外星穹 |

- 存档版本常量只标识当前写入结构；项目尚未发布正式版本，股市和持仓不再执行历史版本迁移。
- 当前结构缺失证券币或持仓字段时使用 0 与空持仓默认值，不从局外星穹自动推导资产，也不缩放旧在线进度。
- 每秒微行情只更新内存；成交、充值和提现立即保存，面板关闭或程序退出时保存最终行情。
- 正式战斗开始后服务暂停自身逐帧处理，在线周期、事件和面板微行情都不推进；战斗结算仍由 `run_state_changed` 信号触发，并在结算完成后恢复局外在线计时。
- 兼容接口可以继续服务旧调用方，但新代码必须使用证券币交易路径。

## 9. 调试与扩展

- 主菜单输入 `LISBAM` 后，开发者菜单可触发全量刷新、小幅刷新、随机事件、大盘切换和清空持仓；清空持仓同时移除全部杠杆仓位与对应止盈止损档案且不返还证券币。
- 新增股票时必须提供稳定 ID、初始价、展示信息和行为映射，并同步机制总表；正式版本发布前不维护旧存档迁移。
- 新增刷新来源时必须明确它是否推进中枢、大盘、周期、事件、行为和矿场联动，禁止复用含义模糊的布尔参数。
- 新增行为采集时只暴露事实接口，保持战斗、库存和 UI 对定价公式无感知。
