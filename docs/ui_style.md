# 窗口 UI 视觉规范

本文档是项目窗口型 UI 的颜色、尺寸、控件状态和接入方式的唯一维护入口。业务规则与交互流程由机制总表和对应模块文档维护；本文件不拥有玩法数据。

## 核心资源

- `res://scripts/ui/ui_style_guide.gd` 是无业务依赖的静态样式指南，集中生成 `Theme` 与 `StyleBoxFlat`，不得读取库存、股市、矿场、战斗或存档服务。
- `res://scripts/ui/dialog_outer_frame.gd` 是无业务依赖的弹窗最外层框架组件，直接绘制不透明标题栏、青蓝轮廓、标题文字和关闭按钮；组件挂载到 `AcceptDialog` 内部全尺寸面板，不依赖 `Window.embedded_border` 或操作系统窗口透明合成。
- `res://scripts/ui/progress_slider_visual.gd` 是无业务依赖的拖动条视觉组件，通过 `ProgressSliderVisual.install(slider)` 挂载到原生 `HSlider`，只绘制轨道、进度和滑块，不接管范围、步长、输入或业务回调。
- `res://scripts/ui/combat_hud_slot_view.gd` 是局内紧凑槽位的唯一纯展示组件，统一左侧主动技能槽与右侧武器槽的背景、边框、圆角、居中文字、冷却遮罩和耐久条；组件不读取技能、装备或输入服务，也不发出点击、拖拽或物品操作请求。
- `apply_screen_theme()` 安装按钮、输入框、下拉框、复选控件、进度条、滑条、滚动条、分隔线、工具提示和弹窗基础主题。
- `apply_window_panel()` 只用于顶层窗口；`apply_section_panel()` 只用于窗口内部装备栏、交易区、统计区和列表区，禁止把全部嵌套面板都提升为主窗口层级。
- `apply_primary_button()` 用于进入、确认、购买、充值、锻造等主要动作；`apply_danger_button()` 用于退出、卖出、清空等高风险动作。普通导航、关闭和返回按钮继续使用默认冷色按钮。
- `apply_title_label()` 统一标题青蓝强调色；业务状态中的收益、亏损、费用和警告仍由对应面板使用语义色覆盖。

## 当前覆盖范围

- 主菜单、主菜单设置、按键绑定、角色选择和战斗内当前角色展示。
- 局外背包、永久仓库、商店、锻造、炒股、矿场和开发者菜单。
- 战斗背包、暂停主菜单、暂停设置、训练场设置、角色切换、暂停地图、大地图遮罩、物资撤离和战斗结算。
- 通用确认、数量选择、证券币转账和强化结果弹窗。
- 所有弹窗通过 `DialogOuterFrame` 在自身全尺寸面板上直接绘制最外层框架，不再依赖引擎 `embedded_border`。自定义标题栏高度 30 像素，标题背景与青蓝描边透明度固定为 1.0，并使用 2 像素描边、10 像素圆角和 8 像素阴影；内容面板继续保留各自的 0.68 或 0.82 半透明背景。
- 数量选择与证券币转账弹窗的确认/取消按钮行保留 8 像素底部净空；通用确认与信息弹窗保留 20 像素底部净空，避免按钮与内层或最外层边框相连。
- 商店购买、矿场购买/出售/充值/提现、正式战斗逃跑、开发者清空仓库和普通信息提示等静态文本弹窗统一使用 `CommonConfirmationDialog.present_adaptive()`：窗口宽度按标题、最长正文行和按钮区在 280 至 520 像素之间计算，正文保留 44 像素水平留白，高度由实际换行后的正文与按钮最小尺寸自动计算，禁止业务面板为短文本硬编码大窗口。
- 股市买卖二次确认继续使用固定 480×270 像素窗口，因为正文和可成交状态每 1 秒刷新；固定尺寸用于防止价格变化期间窗口持续缩放和跳位。
- 矿场交易失败与规则提示统一使用通用信息弹窗，不直接创建原生 `AcceptDialog`；单按钮信息与双按钮确认共享同一背景、边框、按钮和居中展示逻辑。
- 主菜单与暂停设置的 Master 音量、购买/出售/移动/丢弃/送回/矿场交易数量、证券币充值与提现金额滑条统一显示完整范围和当前完成进度。
- 主菜单与暂停设置复用 `SaveTransferControl`：导出与导入按钮位于同一行、等宽伸展，最小高度 42 像素、间距 8 像素；操作结果在按钮下方居中显示，成功使用浅绿色、失败使用浅红色并默认保留 4 秒。文件选择使用系统原生对话框与 `.lisbamsave` 过滤器，不在业务宿主重复实现。
- 主菜单底部局外入口统一放入单个横向容器，左右各保留 24 像素边距，所有按钮等宽伸展；角色入口固定为第一项，禁止继续使用独立绝对坐标排列底部按钮。
- 主菜单底部功能栏在矿场后追加“图鉴”入口。图鉴使用 `1000×640` 像素居中窗口和三枚“武器 / 装备 / 资源”页签；页签下方提供与仓库同款匹配范围的 `260` 像素关键词搜索框，可搜索名称、类型与说明。主体为左右分栏，左侧最小宽度 `280` 像素的单列名称列表；基础内容固定在最前，每份扩展包以 `32` 像素高的居中标题分割，组内条目最小高度 `40` 像素，右侧占用剩余宽度。右侧详情使用左右 `18`、上下 `16` 像素内边距，标题字号 `18`，正文字号 `16`、行距 `4` 像素；富文本自身填满分区并提供内部纵向滚动，不嵌套外层滚动容器，避免长属性信息被裁剪。已解锁列表项显示正式名称，点击后显示图标、类型、说明和完整属性；未解锁列表及详情均只显示“？？？”。
- `VScrollBar` 与 `HScrollBar` 的轨道样式必须提供 14 像素最小可交互厚度。只设置颜色而没有内容边距会使无图标滚动条被引擎压缩为 0 像素，导致 `ScrollContainer` 虽有滚动范围却无法看到或拖动滑块。
- 角色选择按钮统一使用 `CharacterSelectorButton` 主题变体：未选中、未选中悬停、常驻选中和选中悬停分别拥有独立样式。当前角色的常驻选中背景为 RGBA `0.045, 0.285, 0.365, 1.0`，鼠标悬停后提亮到 RGBA `0.075, 0.43, 0.54, 1.0`，不得让 toggle 按钮的选中状态吞掉悬停反馈。
- 角色系统保持原页面边距、左右分栏和底部操作区总体尺寸不变；右侧详情内部改为固定显示垂直滚动条的 `ScrollContainer`。生命上限、能量上限、移速、攻击力和防御力均使用 14 像素高的 `ProgressBar`，默认显示上限依次为 `200、200、140、200、200`，这些上限只决定预览比例，不修改角色真实属性。
- 每个角色技能使用独立 `CharacterSkillCard` 整体边框。第一行左侧显示技能名，右侧依次显示圆角“主动/被动”“CD xxs”“能耗 xx”徽章；徽章最小高度 26 像素、圆角 6 像素、字号 12，技能名字号 17。卡片内容水平/垂直边距为 12/9 像素、标题元素间距为 8 像素；点击标题行展开或收起自动换行的完整说明，悬停或展开时只提高背景与边框亮度，不改变布局尺寸。
- 战斗内当前角色展示直接实例化角色系统场景的单角色模式：隐藏左侧角色列表与确认按钮，详情面板居中并保持 860 像素宽，底部只保留关闭按钮；背景使用统一全屏遮罩，属性条、技能卡片和滚动规则与局外角色系统完全共用，不维护第二套视觉实现。
- 物品卡片和物品操作弹窗继续保留各自独立组件；它们已使用相同深蓝冷色语言，但不得被普通窗口按钮主题替代。
- `ActiveSkillBar` 只向共享视图提供技能按键、名称、能耗和冷却状态；`CombatHud` 直接为右下武器栏创建 `CombatHudSlotView` 并注入装备快照，不再创建或嵌套 `WeaponSlotControl`、`ItemCardView`。因此右下武器栏只作展示，不响应点击、拖拽、修复包投放或强化目标选择；所有装备交互仍在背包界面的标准武器卡牌中完成。技能槽顶部按键、技能名和能耗全部水平居中；武器槽顶部以相同格式居中显示“远程 1 / 远程 2 / 近战”，下方保留武器名、能耗、底部耐久条、选中边框与冷却进度。两侧共享技能 UI 的深蓝黑背景、2 像素青蓝边框、6 像素圆角和同一文本层级。技能栏固定在屏幕左下角，武器槽固定在屏幕右下角，角色名字、生命与能量面板继续位于底部中心；其中能量当前值和上限均四舍五入为整数，不显示小数点，实际 0.1 精度的能量状态与能量条比例保持不变。战斗常驻技能槽与武器槽分别使用 106×50 和 112×54 像素紧凑尺寸；背包、仓库、商店与锻造仍使用 160×72 标准 `ItemCardView`。技能栏属于普通 HUD 绘制层，必须排在全部交互遮罩之前。空槽透明度默认 0.42，技能冷却使用黑色整槽遮罩并显示一位小数秒数。

## 进度拖动条

- 原生 `HSlider` 始终是唯一输入与数值所有者；视觉组件使用忽略鼠标的覆盖层绘制，禁止在视觉组件中连接业务服务或重复实现拖动算法。
- 视觉层每帧比较最小值、最大值与当前值，因此鼠标拖动、键盘调整、业务赋值和 `set_value_no_signal()` 都会刷新已完成进度，不依赖 `value_changed` 信号。
- 轨道按当前控件宽度扣除滑块半径后绘制，最小值和最大值位置均保留边缘空间，避免圆形滑块被自身矩形裁剪。
- 悬停或拖动时进度使用高亮青蓝色，滑块半径由 8 像素临时增加到 9 像素；禁用时改用低饱和灰蓝，但仍保留当前值位置。
- 新增需要显示数值范围的 `HSlider` 时，在控件进入场景树并完成基础属性设置后调用 `ProgressSliderVisual.install(slider)`；重复调用安全返回，不会叠加视觉节点。

## 维护规则

- 新增窗口型 `PanelContainer` 时，根节点先安装统一主题，再应用主窗口样式；内部承载面板默认继承子分区样式。
- 新增可复用 UI 组件时不得直接依赖 `MainMenu` 或 `CombatHud`；组件应自行安装主题，确保在局外和局内宿主中都能独立显示。
- 新增局内技能或常驻武器槽信息时应扩展 `CombatHudSlotView` 的公开内容与状态接口，不得在 `ActiveSkillBar` 和 `CombatHud` 分别创建重复标签、背景或遮罩；`WeaponSlotControl` 只服务背包等物品交互区域。
- 新增 `AcceptDialog` 或 `ConfirmationDialog` 时必须安装 `DialogOuterFrame`，并为正文预留 `DIALOG_TITLE_HEIGHT` 顶部空间；禁止重新使用 `Window.embedded_border` 充当项目弹窗外框，因为其绘制依赖宿主视口的窗口装饰合成。
- 弹窗宿主必须使用 `CommonConfirmationDialog`、`SellQuantityDialog`、`SecuritiesTransferDialog`、`EnhancementResultDialog` 或 `ItemActionPopup` 的具体类型，并通过 `present...` 前缀公开接口展示；禁止退化为原生窗口类型配合字符串 `call()`，避免接口变更只能在运行时发现。
- 纯文本提示与确认优先复用 `CommonConfirmationDialog`；只有包含数量输入、富文本强化结果或物品操作按钮等专用交互时才新增或复用对应专用弹窗。
- 新增正文不会动态变化的确认入口时优先调用 `present_adaptive()`；只有正文持续刷新、富文本滚动区或业务明确要求稳定尺寸时才调用 `present()` / `present_information()` 并传入固定宽高。
- 新增玩家可操作的 `HSlider` 时必须安装 `ProgressSliderVisual`，确保未完成轨道、已完成进度和滑块位置同时可见。
- 业务脚本只允许覆盖具有明确语义的颜色，例如股市涨跌、矿场收益、商店金币、结算获得与丢失；普通控件交互状态必须留在 `UiStyleGuide`。
- 背包、仓库、锻造等动态物品长列表在宿主遮罩隐藏时不得响应库存信号重建卡片；隐藏期间只记录待刷新状态，打开界面时同步一次最新快照。可见状态下同一帧的多个关联信号必须合并为最多 1 次完整列表重建，避免物品数量放大无效 UI 成本。
- 仓库与共享背包刷新长列表时必须按资源实例复用现有标准物品卡片；普通排序移动只更新拖拽来源下标，跨容器移动只处理实际新增和移出的卡片。未变化卡片必须保留悬停缩放、视觉子节点和信号连接，禁止先清空容器再批量重新实例化。
- 调整任一全局颜色、边框、圆角或按钮状态时必须同步更新本文件；只有变化同时影响操作资格或玩法结果时，才更新《游戏机制与玩法内容》。
- 修改主题后至少运行主菜单、角色选择和战斗场景的无窗口启动校验，确保动态创建面板与弹窗都能成功实例化。
- 背包、装备栏、永久仓库及其展开后的随身物品等长列表必须固定显示垂直滚动条，既支持滚轮也支持直接拖动滑块；嵌套滚动区域需分别验证可见性和拖动范围，不能只验证最外层容器。自动验证必须同时断言滚动条像素厚度大于 0、`max_value > page` 且设置 `value` 后实际数值发生变化。

## 12. 护盾与衍生单位展示

- 玩家护盾大于 0 时，生命文本显示“生命 当前/上限  护盾 当前”；护盾归零后移除护盾字段。
- `HealthBar` 上方使用覆盖完整血条的白色滤镜表达当前有护盾，默认透明度 34%；滤镜内部向内缩 1 像素绘制 1 像素宽、92% 不透明度的白色内边框。生命条填充值始终只表示生命比例。
- 具有专属发动条件的主动技能在条件未满足时复用 RGBA `0.16, 0.16, 0.16, 0.72` 禁用滤镜，不显示额外文字；条件满足后移除滤镜。冷却和后续段继续使用各自带秒数遮罩。
- 角色选择与战斗内角色展示在主动技能之后按需显示“衍生单位”，标题字号、颜色、卡片间距、圆角边框与展开交互沿用主动/被动技能规格。
- 衍生单位卡片显示单位名与阵营类型徽章，不显示 CD、能耗；展开后显示攻击类型、可移动状态及全部具体数值。
