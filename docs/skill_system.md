# 角色技能系统

本文档是角色主动技能、被动技能、输入阶段、目标协议和扩展方式的长期维护入口。玩家可见规则与具体数值以 `docs/游戏机制与玩法内容.md` 为准；角色需求原文以禁止 AI 修改的 `docs/扩展包内容.md` 为准。

## 1. 数据结构

- `ActiveSkillData` 保存稳定 ID、显示文本、行为脚本、指向类型、冷却、整数能耗、范围、合法目标组、视线要求、蓄力规则，以及可选的下一段技能资源与释放窗口。
- `PassiveSkillData` 保存稳定 ID、显示文本和行为脚本；需要额外数值的被动应继承该资源类型，在派生数据脚本顶部继续暴露参数。
- `CharacterData.passive_skills` 可以配置任意数量的被动资源；进入主大厅或战斗等可操作角色场景后全部同时创建。
- `CharacterData.active_skills` 可以配置任意数量的主动资源；当前可操作角色输入提供三个槽，因此按数组顺序使用前三个有效资源，其他资源等待未来技能装备界面选择。
- 旧 `passive` 与 `active` 字符串继续作为未迁移角色和隔离场景的详情文本兜底；运行时行为只读取技能资源数组。

每个技能资源只保存模板配置。行为脚本必须创建为独立 `Node`，不得把冷却、命中列表、当前目标或信号连接写入共享 `.tres`。

## 2. 组件职责

| 组件 | 单一职责 |
| --- | --- |
| `ActiveSkillComponent` | 读取三个技能 InputMap 动作，管理按下、瞄准、锁定、蓄力、松手释放、多段槽位切换、能量预检与独立冷却 |
| `PassiveSkillComponent` | 按角色档案创建全部被动行为，并在角色切换时调用 `shutdown()` 后清理旧实例 |
| `SelectedCharacterRuntimeComponent` | 从 `SessionState` 读取当前角色档案，并为主大厅与战斗世界统一注入主动、被动技能资源数组及角色基础属性 |
| `SkillTargetingVisual` | 绘制指向扇形、位置范围、锁定索敌圆与当前目标标记，不参与命中判断 |
| `SkillChargeBar` | 在角色头顶显示当前蓄力比例，由主动技能与武器蓄力组件共用，不拥有蓄力时间 |
| `ActiveSkillBar` | 显示技能一、二、三的实际绑定、当前阶段名称、后续段窗口、冷却和专属发动条件禁用状态，不处理输入或结算 |
| `CombatHudSlotView` | 统一技能槽与战斗常驻武器槽的纯展示外观；技能栏注入按键、名称、能耗与状态，HUD 注入武器快照 |
| `CharacterSkillCard` | 显示角色详情中的技能名、主动/被动类型、基础冷却、基础能耗和可展开说明，不读取角色目录或运行时技能组件 |

`SelectedCharacterRuntimeComponent` 在角色档案应用时把技能资源数组注入两个技能组件；`GameWorld` 继续提供通用技能地图标记等战斗世界接口，`LobbyWorld` 不伪造敌人、宝箱或地图目标。`PlayerController` 不解析技能按键、不保存技能资源，也不实现角色专属效果。

角色系统与战斗内当前角色展示共用 `CharacterSkillCard`。宿主只负责把 `display_name`、`description`、资源实际提供的 `cooldown_duration` 与 `energy_cost` 转换为展示数据；主动技能保持显示 CD 与能耗，被动技能默认隐藏两项徽章，只有对应字段实际大于 0 时才分别显示。每个资源独立生成一张卡片，点击第一行只切换说明可见性，不改变技能槽、冷却、能量或行为实例。旧角色只有 `passive` / `active` 文本时仍生成一张兼容卡片，避免详情为空。

组件与 HUD 的可调布局、颜色、透明度、线宽、采样段数、刷新间隔和组件 `NodePath` 均位于对应脚本顶部的 `@export` 参数；主动技能栏通过 `res://scenes/ui/active_skill_bar.tscn` 暴露单槽样式。资源专属数值位于技能派生数据资源；固定类型编号、除零下限和兼容公式基线位于脚本顶部常量。运行时行为不得在函数体内新增可调魔法数字或按固定子节点名查找角色组件。

## 3. 主动技能输入状态

三个槽默认动作分别为 `active_skill_1`、`active_skill_2`、`active_skill_3`，默认物理键为 C、V、B。它们与其他操作共同进入 `InputBindings` 的保存、改键、单项恢复和全部恢复流程。

`ActiveSkillComponent` 在普通 GUI 与未处理输入阶段之前接收技能动作，但仍以 `PlayerInputComponent` 的战斗输入开关作为唯一启用条件。这样同一渲染帧内完成的按下与松开不会被界面控件截断；背包、地图、暂停、撤离和结算打开时仍不会穿透界面释放技能。

技能行为可选实现无参数 `can_activate()`。组件在输入开始前调用它，并通过 `is_skill_activation_condition_met()` 向 HUD 暴露同一结果；条件不满足时槽位使用统一灰色禁用滤镜且不显示文字。普通行为未实现该方法时默认满足，冷却、能量与目标资格仍由各自既有流程处理。

```text
空闲
  -> 按下可用技能：预检冷却与能量，进入瞄准/蓄力
  -> 持续按住：更新鼠标方向、目标位置或锁定目标；可蓄力技能累计时间
  -> 松开：复核目标与当前能量，执行行为节点
  -> 成功且没有下一段：扣除本段能量，恢复根技能并写入根技能冷却，返回空闲
  -> 成功且存在下一段：扣除本段能量，把原槽替换为下一段，不进入冷却
  -> 后续段成功：继续切换下一段，或在最终段后恢复根技能并写入一次冷却
  -> 后续段超时：恢复根技能并写入一次冷却
  -> 失败或取消：不扣能量、不写冷却，返回空闲
```

打开背包、大地图、暂停、物资撤离、结算或大厅复用局外面板会关闭 `PlayerInputComponent` 的战斗输入。关闭期间移动向量同步归零，并通过信号立即取消正在进行的瞄准和蓄力；重新启用后必须再次按下技能键，不能沿用旧按键状态。成功冲刺同样会调用公开取消接口打断当前主动技能瞄准或蓄力，不释放技能、不扣技能能量且不写入技能冷却；方向无效、能量不足或状态冲突导致冲刺失败时保持原蓄力。

## 4. 三种索敌协议

### 4.1 指向技能

- 按下后显示技能范围；方向模式绘制以鼠标方向为中心的扇形，位置模式绘制最大释放圆和被距离夹取后的目标位置。
- 鼠标贴近角色产生零方向时沿用上一个有效方向。
- 松开后把 `aim_direction` 与 `target_position` 同时写入执行上下文，行为按自身类型选用。

### 4.2 锁定目标技能

- 按下后显示完整索敌圆。
- 合法目标必须位于技能 `target_group`，通过可选的伤害接口、死亡状态、距离和视线复核。
- 组件在全部合法目标中选择世界位置距离鼠标最近者；鼠标移动会切换当前目标。
- 松开时没有合法目标视为取消，不扣能量也不进入冷却；有目标时同时提供 `target`、目标方向与目标位置。

### 4.3 无索敌技能

- 不显示方向或索敌范围。
- 按下后仍可根据资源配置累计蓄力，松开时不要求方向或目标即可调用行为。

## 5. 蓄力与冷却

- `can_charge=false` 时释放上下文的 `charge_ratio` 固定为 `0`。
- 可蓄力技能从按下开始累计 `charge_seconds`，按 `maximum_charge_duration` 限制，超过上限后保持 `charge_ratio=1` 直到松开。
- 可蓄力技能的单击是合法的最低蓄力释放：若按下与松开之间尚未经过处理帧，`charge_seconds=0`、`charge_ratio=0`，行为按未蓄力基础效果执行；该状态不是输入取消或释放失败。
- 主动技能与可蓄力武器共用角色头顶唯一 `SkillChargeBar`；组件以稳定所有者 ID 取得显示，只有当前所有者能更新或隐藏，旧蓄力的延迟取消不得覆盖新蓄力。释放、取消、角色切换或战斗输入关闭后立即清空。
- 成功冲刺会取消当前武器或主动技能蓄力且不触发蓄力攻击或技能效果；冲刺失败不打断蓄力。
- 能量在按下和松开时各预检一次；瞄准或蓄力期间能量被其他动作消耗至不足时，本次松手按取消处理，不执行行为、不扣能量也不进入冷却。
- 每个技能槽独立保存冷却剩余秒数、装备缩减前总时长与实际总时长。只有行为 `execute(context)` 明确返回 `true` 才开始冷却和扣除一次能量；腿部装备冷却缩减只作用于最终进入冷却的根技能，默认 0%，不影响武器或后续段窗口。训练场可通过 `set_cooldown_disabled(true)` 开启角色主动技能无冷却：已有冷却立即归零，成功释放仍扣除技能能量但不写入新冷却；关闭后只影响之后的释放。
- 冷却由实际经过的非负 `delta` 递减到 `0`，技能栏以 0.05 秒固定间隔读取并显示一位小数剩余时间；该 20 Hz 展示采样不改变组件逐帧计时精度。使用“技能结束后再进入冷却”的状态技能会先写入完整冷却并暂停递减；暂停期间槽位仍保持不可用遮罩，但不显示冷却数字，解除暂停并真正开始倒计时后才显示秒数。

### 5.1 多段技能

- 当前段通过 `next_stage` 引用下一段资源，并用 `next_stage_window_duration` 声明释放窗口；两个字段只描述链路，不保存运行时状态。
- 每个槽额外保存根技能、当前阶段、后续段剩余窗口、共享 `chain_state` 和本次完成冷却倍率。行为可在 `chain_state` 中写入位置、生命等跨段数据，但不得写回共享资源；跨阶段世界表现登记到通用 `transient_nodes` 数组后，会在最终段、超时、角色切换或组件离树时统一释放。
- 主大厅允许主动技能组件正常接收输入、消耗能量并写入冷却。依赖 `skill_targets`、宝箱、掉落或战斗世界公开接口的技能在大厅缺少合法对象时继续执行原有取消或失败路径，不创建大厅专用假目标，也不绕过行为的成功返回值。
- 任一中间段成功后不写冷却；最终段成功或等待窗口归零时才恢复根技能，并按 `cooldown_duration × 完成倍率 × (1 - 装备冷却缩减)` 开始整套技能唯一一次冷却。换装、装备损坏或修复期间，已开始冷却保持原有进度比例并换算到新总时长。
- 每一段分别按自身整数 `energy_cost` 预检和扣除。阶段执行失败时不扣能量、不推进阶段，原后续段窗口继续递减。
- 技能栏在等待后续段时显示当前阶段名称和 `N.Ns` 青蓝剩余时间，不额外显示“连段”文字；该状态仍可释放，不视为冷却。
- `execute_pending_stage_immediately()` 供致命伤害回溯等同步机制复用；它仍统一执行能量、释放信号、阶段推进和最终冷却，行为不能绕过组件直接改槽。
- `set_completion_cooldown_multiplier()` 只影响当前整套技能完成后的下一次根冷却，写入冷却后自动恢复 `1.0`；`scale_cooldown_remaining()` 只缩放已经开始的剩余冷却。

## 6. 行为接口

主动行为节点可选实现初始化接口：

```gdscript
func configure(caster: Node2D, stats_component: Node, skill_data: Resource, active_skill_component: Node) -> void
```

必须实现：

```gdscript
func execute(context: Dictionary) -> bool
```

上下文固定包含 `caster`、`stats_component`、`skill_data`、`slot_index`、`aim_direction`、`target_position`、`target`、`charge_seconds`、`charge_ratio` 和当前槽共享的 `chain_state`。强制后续段还会包含 `automatic_release=true` 及调用方覆盖字段。行为返回 `true` 表示成功释放；返回 `false` 表示失败且不结算成本。

被动行为节点应实现：

```gdscript
func configure(caster: Node2D, stats_component: Node, skill_data: Resource, passive_skill_component: Node) -> void
func shutdown() -> void
```

`shutdown()` 必须断开外部信号并移除由该技能稳定 ID 写入的属性来源、地图标记或其他长期状态。不同被动不得使用同一个来源 ID。

## 7. 目标与属性协议

- 通用技能目标加入 `skill_targets` 组；开拓！！可计数单位加入 `skill_presence_units` 组。
- 当前怪物通过 `active_skill_target_group` 与 `presence_skill_unit_group` 检查器参数在 `_ready()` 中加入两个组；空组可分别关闭对应资格。宝箱组由星的两个被动资源各自配置为 `loot_chests`，不作为银河全垒打目标，但参与开拓！！计数。
- 距离型击退技能可读取目标 `get_knockback_decay()` 并用 `v=sqrt(2ad)` 换算初始速度；银河全垒打则直接提供理论位移冲击力，由怪物统一按韧性和自身击退衰减换算，墙体仍会缩短实际位移。
- `CombatStatsComponent.set_skill_stat_multiplier(source_id, attack_ratio, defense_ratio)` 以稳定来源覆盖写入。不同来源按 `∏(1+比例)` 连乘，相同来源重复刷新不会自我叠加。
- “增伤”与“造成的伤害提高”统一保存为同一增伤乘区的比例，各来源直接加算后形成 `1 + 总增伤比例`；自带蓄力增伤的武器或技能也把蓄力比例加入该乘区，不再与玩家增伤相乘。
- “免伤”与“受到的伤害降低”统一保存为同一免伤乘区的比例，各来源直接加算并限制到 `0%–100%`，最终剩余伤害倍率为 `1 - 总免伤比例`。
- 角色属性面板把被动产生的攻防点数、主动技能提供的固定移速点数及其他全部非基础来源统一计入“额外值”；二倍速受击衰减或结束时即时刷新。

## 9. 穹的技能资源

| 技能 | 类型 | 资源 | 行为 |
| --- | --- | --- | --- |
| 拾荒 | 被动 | `res://data/skills/caelus/scavenging.tres` | 成功撤离完成物品结算前统计 `item_drops` 组剩余掉落物有效价值，按 20% 向下取整发放星穹；失败、逃跑和训练场不触发 |
| 炎枪，冲锋！ | 指向主动、可蓄力 | `res://data/skills/caelus/firewall_charge.tres` | 单次能耗 20；20 秒冷却；基础冲锋 1 秒，实际蓄力最多 2 秒并等量延长；速度为当前移速属性+150；期间不可操控且减伤 80%；42 像素半径内每个目标只命中一次，威力为 10+20%最终防御力，50 点冲击沿冲锋垂直方向推向两侧；正面撞墙立即结束 |

穹的主动技能占技能一。冲锋释放后由行为节点维护命中去重、撞墙提前结束与减伤来源，由玩家控制器维护强制物理移动并只公开本物理帧是否受墙体阻挡；两者使用相同持续时间。角色切换或行为节点退出树时必须同时移除 `caelus_firewall_charge` 减伤来源并取消强制移动，不能遗留到其他角色。

拾荒统计普通地面节点时按 1 件计价；玩家整组丢弃形成的强化石、修复包或消耗品堆叠节点按节点保存的 1 至 10 实际数量计价，因此单节点优化不会减少或增加剩余掉落物总价值。

## 11. 新技能接入

1. 复制相同类型数据资源并填写唯一 `skill_id`、正式名称、说明和全部数值。
2. 创建单一职责行为脚本；通用输入或目标规则应进入技能组件，不要复制到角色行为。
3. 把被动或主动资源加入目标角色的对应数组；一个角色可同时引用多个资源。
4. 新伤害目标显式加入目标组并实现需要的公开接口；不要按节点名或场景路径硬编码识别。
5. 同步角色详情、`docs/游戏机制与玩法内容.md` 中的全部具体数值和本文件的扩展协议。
6. 验证空槽、冷却、能量不足、无合法目标、输入取消、同帧单击的 `0 秒/0%` 最低蓄力、持续按住与满蓄力、范围边界、遮挡、多目标和角色切换清理。
7. 多段技能还要验证每一段能量、技能槽名称、窗口边界前/等于/超时、最终冷却、强制触发、角色切换清理和 `chain_state` 不跨释放残留。

## 12. 衍生单位与新增星技能

- `CharacterData.derived_units` 引用 `DerivedUnitData`。资源保存单位场景、可移动状态、攻防、生命、视野、伤害、攻击距离、冷却、坐力与冲击；运行时生命、目标和限时增益只保存在单位实例。
- 主动技能组件提供按来源暂停槽冷却的接口。二倍速与穹的星尘王牌在状态期间暂停完整冷却，状态结束后解除暂停并开始递减；固定秒数减 CD 使用 `reduce_cooldown_remaining()`。
- 银河全垒打现造成 `10 + 10%最终攻击力` 的未蓄力威力，命中目标后写入持续 10 秒的标记；蓄力 3 秒仍最多提高 80% 伤害和冲击，基础冲击 150、满蓄 270，前坐力 80 至 150。
