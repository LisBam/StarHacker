# 项目文档导航

本目录保存项目长期有效的玩法、架构、内容制作、界面和验证规范。文档只记录需要跨文件理解的规则；能够直接从单个脚本导出变量或资源检查器读取的字段，不再重复抄录。

## 文档索引

| 文档 | 权威范围 | 适用场景 |
| --- | --- | --- |
| `游戏机制与玩法内容.md` | 玩家实际体验、玩法公式、概率、时间、费用和默认数值 | 设计校验、平衡调整、功能验收 |
| `game_framework.md` | 场景入口、系统分层、组件职责、数据流、存档边界和扩展协议 | 定位实现、设计新模块、排查耦合 |
| `content_authoring.md` | 内容目录、稳定 ID、自动发现、扩展包与套装创建步骤和接入范围 | 新增武器、装备、道具、角色、怪物、套装或扩展包 |
| `skill_system.md` | 主动/被动技能数据、输入状态、索敌、蓄力、行为接口和角色接入协议 | 新增或维护角色技能、技能 HUD、目标组与技能倍率 |
| `enemy_ai.md` | 敌人感知、记忆、战术、移动与虚拟人口的协作边界 | 维护敌人 AI 和性能加载 |
| `stock_market.md` | 股市服务、刷新来源、行为采集、交易与持久化边界 | 维护局外股市系统 |
| `mining_farm.md` | 矿场服务、在线结算、资产、联动与持久化边界 | 维护量子算力矿场 |
| `ui_style.md` | 全局颜色、尺寸、控件状态、弹窗和复用规则 | 新增或调整 UI |
| `功能验证测试规范.md` | 验证门禁、测试范围、存档安全和报告格式 | 所有功能、资源和文档改动验收 |
| `扩展包内容.md` | 角色扩展包的需求原文、正式名称和权威内容数值 | 实现或验收角色专属扩展包；该文件禁止 AI 修改 |

## 阅读路径

- 理解玩家规则：先读 `游戏机制与玩法内容.md`，再按模块进入专用文档。
- 理解代码结构：先读 `game_framework.md`，再查看其中列出的责任脚本。
- 新增游戏内容：直接按 `content_authoring.md` 操作；不要手工维护重复资源清单。
- 验证改动：按 `功能验证测试规范.md` 选择测试范围，并同步对应模块文档。

## 事实来源

同一信息存在冲突时，按以下顺序校验并修正文档：

1. 场景中的检查器覆盖值与实际 `.tres` / `.tscn` 资源。
2. 脚本常量、导出变量默认值和运行时公式。
3. 《游戏机制与玩法内容》中的玩家规则与数值快照。
4. 模块文档中的架构说明。

规划内容必须明确标注“未实现”，不得与当前玩法混写。历史迁移规则仅在仍需兼容现有存档时保留；已经移除且不再影响维护的旧实现不写入主流程。

## 主要目录

| 路径 | 职责 |
| --- | --- |
| `res://data/` | 角色、武器、装备、道具、套装和扩展包清单资源 |
| `res://scripts/data/` | 数据资源类型与数值规则 |
| `res://scripts/components/` | 可组合的移动、战斗、库存、感知和敌人组件 |
| `res://scripts/game/` | 世界、内容目录、库存、商店、锻造、股市、矿场和会话服务 |
| `res://scripts/ui/` | 主菜单、HUD、仓库、商店、锻造、地图和通用控件 |
| `res://scenes/` | 角色、敌人、环境、弹体、掉落和界面组合场景 |
