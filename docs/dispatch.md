# 佣兵派遣

本文档说明佣兵派遣系统的服务职责、委托数值、角色锁定协议与持久化边界。玩家可见数值以《游戏机制与玩法内容》为准。

## 1. 系统定位

- 派遣让已解锁但未上场的角色在局外产生收益：签订限时委托、在线倒计时、到期自动交付星穹报酬。
- 每个委托绑定一项适性属性；角色对应属性越高，大成功（报酬 ×1.5）概率越高，从而让角色面板数值在局外也有意义。
- 每名未上场角色可同时执行一项委托；委托不占用全局队列，因此其他闲置角色可继续签订任意委托类型。
- 派遣中的角色被锁定，不能在角色选择页确认上场；当前上场角色不能被派遣，因此上场角色与派遣角色永不重叠。

## 2. 服务与职责

| 部分 | 实现 | 职责 |
| --- | --- | --- |
| 派遣服务 | `res://scripts/game/dispatch_service.gd`（AutoLoad `DispatchService`） | 维护委托目录、进行中派遣、在线倒计时、大成功判定、完成报告与独立存档 |
| 派遣面板 | `res://scripts/ui/dispatch_panel.gd` | 角色选择行 + 五张委托卡 + 多张进行中/报告卡；派遣走二次确认 |
| 角色锁定 | `character_select.gd` | 通过 `is_character_dispatched()` 禁用确认按钮（文案“派遣中，无法上场”）、列表名称追加“（派遣中）”，确认瞬间二次复核 |
| 主菜单入口 | `main_menu.gd` 底部“派遣”按钮与大厅 `dispatch` 动作 | 动态创建遮罩与面板 |

## 3. 委托目录与数值

| 委托 | 稳定 ID | 在线时长 | 基础报酬 | 适性属性 |
| --- | --- | ---: | ---: | --- |
| 情报收集 | `intel_sweep` | 600 秒（10 分钟） | 50 星穹 | 移动速度（`move_speed`） |
| 前线驻守 | `garrison_watch` | 1200 秒（20 分钟） | 107 星穹 | 生命上限（`max_health`） |
| 遗迹护送 | `relic_escort` | 1800 秒（30 分钟） | 175 星穹 | 防御力（`defense_power`） |
| 能源网巡检 | `energy_grid_patrol` | 2400 秒（40 分钟） | 249 星穹 | 能量上限（`max_energy`） |
| 深网渗透 | `deep_net_raid` | 3000 秒（50 分钟） | 333 星穹 | 攻击力（`attack_power`） |

- 报酬效率按时长递增（约 300 / 321 / 350 / 374 / 400 星穹每在线小时），奖励长线锁定；平衡口径见机制总表第 25 章。
- 五档适性正好覆盖角色档案五维；面板委托卡为流式布局，每行最多三张、超出自动换行滚动。

- 锁定报酬 = `floor(基础报酬 × (1 + 佣兵联络站加成))`，签订瞬间确定。
- 大成功概率 = `clamp(15% + (适性属性 − 90) × 0.5%, 5%, 50%)`，签订瞬间按角色档案锁定；交付时一次性判定，大成功实际到账 = `floor(锁定报酬 × 1.5)`。
- 属性读取 `SessionState.get_character_profile()` 的 `attack_power` / `defense_power` / `move_speed` 字段，档案缺失按基准值 90 处理。
- 每名角色同一时间最多一个进行中委托，中途不可召回；不同未上场角色可并行，倒计时只消耗在线时间。

## 4. 交付与报告

- 倒计时归零自动交付：`adjust_coins` 发放报酬、写入完成报告、广播 `dispatch_completed`（横幅“【派遣归来】”）并解除对应角色锁定。同一帧有多条委托到期时会逐条发出完成通知。
- 完成报告随存档持久化，按完成时间倒序保留最近 10 份；面板在无进行中派遣时展示最新的“上次委托报告”卡片，大成功使用金色语义。
- 签订校验依次为：委托合法、角色标识有效、该角色尚未派遣、角色已解锁、角色非当前上场；全部通过才锁定该角色，不检查其他角色是否已有委托。

## 5. 持久化

- 独立写入 `user://dispatch_state.json`，版本 2；以 `active_dispatches` 数组保存每名角色的进行中委托（委托 ID、角色 ID、角色名、剩余在线秒数、锁定报酬、锁定大成功率），并保存最近 10 份 `recent_reports` 与兼容用的最新 `last_report`。
- 交付发放走 `_flush_linked_saves()` 与星穹存档同路径落盘；倒计时按 0.5 秒合并写盘，战斗期间挂起。
- 版本 1 的单条 `active_*` 记录会在读取时迁移到版本 2 数组，原剩余在线时间与锁定报酬保持不变；迁移后回写新结构。
- 读档时单条委托数据异常（委托被移除、角色为空或重复、剩余时间或报酬非法）直接结束该条派遣且不发放报酬，不影响其余有效委托。
- 文件已加入存档白名单，随导出、导入与删除统一处理。

## 6. 扩展注意

- 新增委托只需在 `MISSION_DEFINITIONS` 追加条目；适性属性必须使用角色档案中的现有字段名。
- `is_character_dispatched()` 保持单角色查询签名；多角色 UI 应使用 `get_active_dispatch_snapshots()` 读取全部快照，旧调用方可继续使用 `get_active_dispatch_snapshot()` 获取排序后的首条快照。
- 删除或导入存档会重置派遣状态；角色锁定完全跟随派遣存档，不写入角色解锁存档。
