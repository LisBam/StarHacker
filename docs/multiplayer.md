# 局域网联机

本文档是《星穹骇客（Star Hacker）》局域网联机模块的唯一维护入口，说明会话服务、组队面板、战斗同步架构、消息协议与已知边界。玩家可见规则与数值同步维护在 `docs/游戏机制与玩法内容.md`；敌人傀儡协议的怪物侧实现细节见 `docs/enemy_ai.md`。

## 1. 模块组成

| 模块 | 实现 | 职责 |
| --- | --- | --- |
| 会话服务 | `scripts/game/network_session.gd`（AutoLoad `NetworkSession`） | ENet 建房与加入、UDP 局域网房间发现、成员名册与准备状态、共享地图种子分发、统一开局切场景、战斗消息中继 |
| 联机面板 | `scripts/ui/multiplayer_lobby_panel.gd`（`MultiplayerLobbyPanel`） | 960×620 居中窗口（标题“联机”）；昵称编辑、房间列表、直连 IP、模式选择（组队骇入 / 大逃杀）、成员名册、准备与开始骇入入口 |
| 联机大厅 | `scenes/game/multiplayer_lobby.tscn`、`scripts/game/multiplayer_lobby_world.gd`（`MultiplayerLobbyWorld`，继承 `LobbyWorld`） | 主菜单“联机”按钮（与“训练场”并排同一行）的目标场景；进场自动打开联机面板，左上角“切换大厅/菜单”下方提供“联机设置”按钮重新打开面板，1600×1000 场地无交互设施 |
| 大厅在场同步器 | `scripts/game/network_lobby_sync.gd`（`NetworkLobbySync`） | 联机大厅内的成员互见：20Hz 广播带 `ctx=lobby` 的玩家状态包并以化身展示同房间成员；无伤害转发，成员停止发包 1.6 秒后按在场超时移除化身 |
| 战斗同步器 | `scripts/game/network_combat_sync.gd`（`NetworkCombatSync`） | 联机骇入局内唯一实体复制协调者；由 `GameWorld` 在联机模式下动态创建，节点组 `network_combat_sync` |
| 队友化身 | `scripts/player/remote_player_avatar.gd`（`RemotePlayerAvatar`） | 远程玩家在本机世界的代表；外观、昵称、生命护盾条、敌人可索敌可命中、受击转发 |
| 伤害代理 | `scripts/game/network_damage_proxy.gd`（`NetworkDamageProxy`） | 在本机重建远程伤害来源的战斗数值接口（攻击力、暴击、冲击力、击退方向、位置） |

`NetworkSession` 是 AutoLoad 注册清单中的最后一项，`process_mode = ALWAYS`，场景切换与暂停都不会中断连接；它不写入任何存档文件。

## 2. 会话流程

0. 入口：完整主菜单点击“联机”经统一转场进入联机大厅，进场自动打开联机面板；左上角“联机设置”按钮可随时重新打开。面板打开期间大厅按既有聚合信号锁定玩家控制；关闭面板后可在大厅内自由移动等待。返回主菜单不断开房间连接。
1. 建房：主机 `create_room()` 在端口 `24857` 创建 ENet 服务器（上限 4 人），同时绑定 UDP 端口 `24858` 应答房间探测。
2. 发现：客户端面板可见且未入房时，按 1 秒间隔向 `255.255.255.255:24858` 广播探测串；主机回复 JSON 房间信息（房名、人数、版本、是否战斗中），3 秒未刷新的房间条目自动过期。
3. 加入：从房间列表选中或直接输入 IP 调 `join_room(ip)`；握手成功后客户端提交个人档案（昵称、当前角色、准备状态）进入名册，名册由主机权威维护并全量广播。
4. 模式：主机通过 `set_session_combat_mode()` 在 `team`（组队骇入，默认）与 `battle_royale`（大逃杀）之间切换；切换会清空全员准备并经 `_rpc_sync_combat_mode` 同步，新成员入册时补发当前模式，房间发现回复也携带模式供房间列表标注。
5. 开局：全员准备且成员数 ≥ 2 时主机 `request_start_combat()` 生效；主机生成非零共享种子并广播 `_rpc_begin_combat(seed, mode)`（开局指令再次携带模式作为最终权威），每个成员各自写入 `SessionState` 骇入模式并经 `SceneTransition` 进入 `game_world.tscn`。正处于战斗场景或转场中的成员会忽略开局指令。
6. 离场：任一成员离开战斗场景时广播离场事件并调用 `notify_combat_scene_exited()`；网络连接与名册保持，回到主菜单可直接准备下一局。开局后全员准备状态自动清零。

战斗消息通道：`broadcast_combat_message(payload, reliable)` 与 `send_combat_message(peer_id, payload, reliable)`，底层是 `NetworkSession` 自身的两个 RPC（可靠 / 不可靠有序）。消息始终以 `combat_message_received(sender, payload)` 信号交给战斗同步器，联机代码不在业务节点上注册任何 RPC 路径。

## 3. 世界一致性模型

- 地图确定性复现：共享种子覆盖 `GameWorld.map_seed`，边界墙、随机环境、宝箱布点与品质、物资撤离点全部由同一随机流生成，不经网络传输。
- 撤离点确定性：联机时 `GameWorld` 在进图当帧用 `共享种子 + 7717` 的专用随机流预推导撤离点位置（此刻各端环境缓存与玩家位置完全一致），120 秒后直接使用；单机保持原实时随机。
- 运行期动态状态（敌人、掉落、宝箱开启、玩家状态）全部经消息同步，见下节。

## 4. 战斗同步架构

### 4.1 队友化身（全员对等）

- 每端以 20Hz（`player_state`，不可靠有序）广播本地玩家位置、瞄准角、生命、护盾与死亡状态；其余成员的化身按 14/s 指数插值跟随，偏差超过 220 像素直接落位。
- 化身在玩家物理层（layer 1）、加入 `player_combat_target` 组并实现 `apply_damage` / `is_dead()`，因此主机敌人可以索敌、近战命中、弹体扫掠命中队友。
- 主机敌人命中化身后不在主机结算，而是把伤害与来源战斗数值（`player_hit`）定向发给该成员；受害端用 `NetworkDamageProxy` 重建来源并走本地完整受击流程（闪避、防御、护盾、击退、受伤间隔全部按受害者自身属性结算）。
- 队友开火视觉：订阅本地 `RangedAttackComponent` / `HybridRangedAttackComponent` 的 `fired` 信号，广播弹体场景路径与真实速度向量（`player_fire`）；远端实例化同场景弹体但清零碰撞与伤害。弹体场景路径仅接受 `res://scenes/projectiles/` 前缀。

### 4.2 主机权威敌人

- 只有主机运行虚拟人口、物化、AI 与人口补充；客户端 `GameWorld` 跳过 `MonsterSimulationManager.initialize`、开局布怪与补怪循环。
- 主机每 0.1 秒扫描 `training_monsters` 组内真实敌人：新节点分配自增网络编号并广播 `enemy_add`（场景路径、位置、体型与属性倍率、生命）；消失节点广播 `enemy_remove`（死亡带 `died=true` 与击杀归属，休眠为静默移除）；存活节点打包 `enemy_state` 快照（每条最多 16 项，附带全图人口数）。
- 客户端按 `enemy_add` 实例化同场景怪物并调用 `enter_network_puppet_mode()` 进入傀儡模式：物理帧停用、不注入索敌目标（不会误发遇敌信号）、位置由快照插值、生命采用主机权威值；死亡移除播放原版死亡动画。傀儡场景路径仅接受 `res://scenes/enemies/` 前缀。
- 客户端攻击傀儡：傀儡在受击端用与单机完全相同的公式完成攻防与暴击结算并立即显示飘字，然后把最终伤害转发主机（`enemy_hit`）；主机调用 `receive_network_final_damage()` 直接执行护盾、生命、飘字、仇恨与击退，不做二次攻防计算。击杀归属随 `enemy_remove` 回传，本机击杀触发本地套装击杀通知。
- 队友锚点：主机把全部化身注册为 `MonsterSimulationManager` 的额外物化锚点，靠近任一队友的虚拟敌人照常实例化，正在与队友交战的敌人不会因远离主机被休眠。
- 人口缩放：联机人口倍率为 `1.5^(成员数-1)`，按开局名册人数固定整局；作用于开局布怪数量、人口曲线三段目标与同时活跃真实敌人上限（基础 220 同步放大），全部只在主机侧生效，客户端经快照头感知放大后的人口读数。
- 敌方弹体视觉：主机远程怪物开火后广播 `enemy_shot`（出膛位置、含散布的最终方向、速度）；客户端生成伤害为零、掩码为零的视觉弹体，保留敌方弹体层使玩家近战仍可清除其视觉体。

### 4.3 掉落物与宝箱

- 任何一端本地产生的掉落（怪物死亡、宝箱出货、玩家丢弃）都经 `GameWorld` 掉落生成钩子登记网络编号（`peer_id_序号`）并广播 `drop_add`；物品用 `GlobalInventory.serialize_item_snapshot()` 稳定快照跨端还原，强化、耐久与二手状态完整保留。
- 拾取仲裁：主机维护存活掉落集合，先到先得。客户端拾取先发 `drop_request`，主机批准后先回 `drop_grant` 再广播 `drop_remove`（同链路顺序保证先入包再消失）；批准后入包失败（背包满）时该掉落以新编号重新广播回世界。主机自身拾取本地直接结算并广播移除。请求 2 秒未获答复自动放弃，以移除广播为最终一致依据。
- 宝箱仲裁：宝箱位置键（0.1 像素量化）作为全端一致的稳定标识。开箱完成的一端向主机发 `chest_claim`；主机先到先得，向认领者回发出货参数（`chest_grant`），并广播 `chest_gone` 让其余端调用 `LootChest.force_network_remove()` 静默移除同位置宝箱（不出货、不重复上报开箱统计）。出货掷点由认领端本地执行，套装追加数量按认领者自己的装备结算。

### 4.4 大逃杀模式

- 出生点表：`GameWorld` 用 `共享种子 + 15473` 的专用随机流按 peer_id 升序为每名成员推导出生点（离边缘 ≥ 640 像素、两两间距 ≥ 1600 像素、避开环境障碍，48 次尝试后回退最后候选）；推导在布怪之前、传送在布怪之后执行，各端结果逐位一致，不经网络传输。
- 出生保护：主机开局布怪与人口补充的候选点同时避开全部大逃杀出生点与 `player_combat_target` 组内所有存活单位周围 `monster_spawn_min_distance`（900 像素），防止玩家降生或游走时敌人贴身刷新；该保护对组队模式的队友同样生效。
- 玩家互伤：大逃杀下化身碰撞层为 `玩家层|怪物层`（3），本机玩家的弹体（掩码含第 2 层）与近战命中框可以命中它；命中后化身播放 0.14 秒提亮反馈并把伤害与来源战斗数值经既有 `player_hit` 链路转发给受害者，由受害者本地按自身闪避、防御与护盾结算，与 PvE 使用同一攻防公式。组队模式化身只在玩家层，本机攻击直接穿过队友，天然关闭友军伤害。
- 其余系统（敌人复制、掉落、宝箱、撤离、结算）与组队模式完全一致；玩家死亡执行本地死亡结算，按概率丢失的物品不会掉落到地面。

### 4.5 死亡观战

- 触发：战斗 HUD 的死亡入口先询问同步器 `try_begin_spectator_mode(结算回调)`；仍有存活队友（化身有效、未离场、远端状态未死亡）时返回 true，死亡结算被推迟，同步器接管视角。单机、训练场或无人存活时该入口返回 false，HUD 走原即时结算。
- 视角：同步器创建复用的 `SpectatorCamera`（缩放沿用玩家战斗相机），切换目标时镜头直接落位，随后以 8/s 速率平滑跟随目标化身；观战不产生任何新增网络消息，画面完全来自既有化身状态与敌人复制。
- 界面：`CanvasLayer` 层级 54；顶部横幅“观战中：昵称·角色”，屏幕左右边缘垂直居中各一个 64×96 像素箭头按钮在存活队友间按 peer_id 升序循环切换，底部“结算退出”按钮主动结束观战。
- 结束：目标死亡或离场自动切到下一名；全部队友倒下、离场（含主机离场）或玩家点击“结算退出”后，恢复本地玩家相机并调用结算回调执行原死亡结算，重复结算由 HUD 的结算完成标记保护。

### 4.6 成员事件与降级

- 事件广播（`event`）：`player_dead`（倒下提示）、`player_left`（移除化身）、`host_left`（主机离场）。提示以屏幕上方 3 秒渐隐文本显示（`CanvasLayer` 层级 55）。
- 主机离场或与主机断连：客户端清空全部傀儡敌人、人口清零，并提示“主机已离开战斗，敌人已撤除，请尽快撤离”；拾取与宝箱降级为本地直接结算。撤离点位置在进图时已确定，不受主机离场影响。
- 成员断线：名册变化驱动化身移除与断线提示；战局中途不允许新成员加入（主机在战斗会话激活期间拒绝新连接）。

## 5. 联机模式下的既有系统行为差异

- 战斗界面不暂停世界：`CombatHud` 全部 `get_tree().paused` 写入统一经 `_set_battle_tree_paused()`，联机战斗中背包、大地图、角色展示、暂停菜单、物资撤离面板与死亡结算都不冻结场景树；战斗输入仍按原逻辑关闭。返回主菜单路径保持无条件解除暂停。
- 结算完全本地化：撤离、死亡与逃跑结算沿用单机规则，各成员只结算自己的背包与装备；物资撤离点送回同样只操作本人仓库。
- 敌人索敌：`BasicMonster` 的玩家阵营候选从“第一个组成员”改为“视野内最近组成员”，单机行为不变（组内只有一名玩家），联机时本地玩家与化身平等竞争仇恨；受伤仇恨规则不变。
- 图鉴解锁：傀儡不注入索敌目标因此不派发遇敌信号；客户端图鉴解锁依赖主机侧遇敌链路不受影响，属于已知联机差异（见第 7 节）。

## 6. 消息协议速查

| 类型 | 方向 | 通道 | 内容 |
| --- | --- | --- | --- |
| `player_state` | 全员互播 | 不可靠 | 位置、瞄准角、生命、护盾、死亡；`ctx` 字段区分 `combat` 与 `lobby` 场景上下文，战斗同步器只消费 combat、大厅同步器只消费 lobby，防止身处不同场景的成员状态互相串扰 |
| `player_fire` | 全员互播 | 不可靠 | 弹体场景路径、出膛位置、速度向量、最大距离 |
| `player_hit` | 主机→受害者 | 可靠 | 伤害、攻击力、暴击、冲击力、击退方向、来源位置 |
| `enemy_add` / `enemy_remove` / `enemy_state` | 主机→客户端 | 可靠 / 可靠 / 不可靠 | 敌人生成参数 / 移除与击杀归属 / 位置生命快照与全图人口 |
| `enemy_hit` | 客户端→主机 | 可靠 | 敌人编号、最终伤害、暴击、冲击力、击退方向 |
| `enemy_shot` | 主机→客户端 | 不可靠 | 敌方弹体出膛位置、方向、速度 |
| `drop_add` / `drop_remove` / `drop_request` / `drop_grant` | 见 4.3 | 可靠 | 掉落编号、物品快照、数量、落点与飞出参数 |
| `chest_claim` / `chest_grant` / `chest_gone` | 见 4.3 | 可靠 | 宝箱位置键与出货参数 |
| `event` | 全员互播 | 可靠 | `player_dead` / `player_left` / `host_left` 与成员编号 |

## 7. 已知边界与后续方向

- 首次建房或加入时 Windows 防火墙会弹出放行提示；未放行会导致房间发现失败，可用直连 IP 兜底（ENet 与发现使用不同端口，均需放行）。
- 全局广播 `255.255.255.255` 在少数多网卡或路由器隔离环境下不可达；此时使用直连 IP 加入。
- 召唤类友方衍生单位仅在召唤者本机存在并参战；其对傀儡的伤害正常转发主机，但其他成员看不到该单位本体。
- 大逃杀的玩家互伤只覆盖远程与近战武器；主动技能的索敌目标组不包含玩家化身，技能不会锁定或伤害其他玩家。
- 大逃杀击杀其他玩家不掉落其物品；被击杀者按单机死亡结算概率丢失物品，丢失部分直接进入其个人结算，不生成地面掉落。
- 客户端图鉴不会因“傀儡出现在屏幕上”解锁；怪物图鉴解锁仍以本机有效遇敌链路为准。
- 极小概率的并发边界（例如主机离场降级后的同帧双拾取）以“可重复拾取但不丢失物品”为容错方向，不做回滚。
- 战局中途不支持加入；断线成员需回到主菜单重新加入房间并等待下一局。
- 主大厅暂未放置“联机组队”实体设施；`perform_lobby_action("multiplayer")` 已注册，未来在 `main_lobby.tscn` 增加一个 `LobbyInteractable` 即可接入。

## 8. 验证要点

- 无头导入与主菜单、单机战斗无头运行必须零错误（联机代码在单机路径不创建任何节点）。
- 双实例端到端验证：同机以两份隔离用户目录（覆盖 `APPDATA` 环境变量；Godot 4.7 无 `--user-data-dir` 参数）启动主机与客户端，走完建房→加入→准备→统一开局→进入战斗；断言两端 `player_combat_target` 组均为 2、主机真实敌人数与客户端傀儡数一致、两端人口读数与共享种子一致。
- 大逃杀模式额外断言：两端会话模式均为 `battle_royale`、本机玩家位置与对端化身位置互相吻合（确定性出生点与状态同步双重验证）、出生间距不低于 1600 像素、化身碰撞层为 3、出生 7 秒后双方生命保持满值（出生保护有效）；组队模式回归须确认不输出大逃杀采样，即分散出生与互伤均未误开。
- 人口缩放断言：双人局采样人口应约为同期单人基线的 1.5 倍（例如同一采样时刻 226→339），两端读数一致。
- 观战断言：自杀实例在死亡后 `is_spectator_active()` 为 true、当前视口相机为 `SpectatorCamera` 且镜头到目标化身距离约 0，截图应显示观战横幅、左右箭头与“结算退出”按钮且无死亡结算遮罩；存活实例观战状态保持 false 且相机仍为玩家相机。
- 以 `.` 开头的临时场景或脚本会被 Godot 文件系统忽略而无法作为启动场景加载；双实例驱动脚本需使用普通文件名并在验证后删除。端到端驱动的场景根节点派生常驻副本后必须 `set_process(false)`，否则场景根会以未解析的默认参数与副本竞争驱动会话。
