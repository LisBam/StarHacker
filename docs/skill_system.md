# 角色技能系统

本文档是角色主动技能、被动技能、输入阶段、目标协议和扩展方式的长期维护入口。玩家可见规则与具体数值以 `docs/游戏机制与玩法内容.md` 为准；角色需求原文以禁止 AI 修改的 `docs/扩展包内容.md` 为准。

## 1. 数据结构

- `ActiveSkillData` 保存稳定 ID、显示文本、行为脚本、指向类型、冷却、能耗、范围、合法目标组、视线要求与蓄力规则。
- `PassiveSkillData` 保存稳定 ID、显示文本和行为脚本；需要额外数值的被动应继承该资源类型，在派生数据脚本顶部继续暴露参数。
- `CharacterData.passive_skills` 可以配置任意数量的被动资源；进入战斗后全部同时创建。
- `CharacterData.active_skills` 可以配置任意数量的主动资源；当前战斗输入提供三个槽，因此按数组顺序使用前三个有效资源，其他资源等待未来技能装备界面选择。
- 旧 `passive` 与 `active` 字符串继续作为未迁移角色和隔离场景的详情文本兜底；运行时行为只读取技能资源数组。

每个技能资源只保存模板配置。行为脚本必须创建为独立 `Node`，不得把冷却、命中列表、当前目标或信号连接写入共享 `.tres`。

## 2. 组件职责

| 组件 | 单一职责 |
| --- | --- |
| `ActiveSkillComponent` | 读取三个技能 InputMap 动作，管理按下、瞄准、锁定、蓄力、松手释放、能量预检与独立冷却 |
| `PassiveSkillComponent` | 按角色档案创建全部被动行为，并在角色切换时调用 `shutdown()` 后清理旧实例 |
| `SkillTargetingVisual` | 绘制指向扇形、位置范围、锁定索敌圆与当前目标标记，不参与命中判断 |
| `SkillChargeBar` | 在角色头顶显示当前蓄力比例，不拥有蓄力时间 |
| `ActiveSkillBar` | 显示技能一、二、三的实际绑定、名称和冷却，不处理输入或结算 |

`GameWorld` 只在角色档案应用时把技能资源数组注入两个技能组件，并提供通用技能地图标记接口。`PlayerController` 不解析技能按键、不保存技能资源，也不实现角色专属效果。

组件与 HUD 的可调布局、颜色、透明度、线宽、采样段数、刷新间隔和组件 `NodePath` 均位于对应脚本顶部的 `@export` 参数；主动技能栏通过 `res://scenes/ui/active_skill_bar.tscn` 暴露单槽样式。资源专属数值位于技能派生数据资源；固定类型编号、除零下限和兼容公式基线位于脚本顶部常量。运行时行为不得在函数体内新增可调魔法数字或按固定子节点名查找角色组件。

## 3. 主动技能输入状态

三个槽默认动作分别为 `active_skill_1`、`active_skill_2`、`active_skill_3`，默认物理键为 C、V、B。它们与其他操作共同进入 `InputBindings` 的保存、改键、单项恢复和全部恢复流程。

```text
空闲
  -> 按下可用技能：预检冷却与能量，进入瞄准/蓄力
  -> 持续按住：更新鼠标方向、目标位置或锁定目标；可蓄力技能累计时间
  -> 松开：复核目标与当前能量，执行行为节点
  -> 成功：扣除一次能量，写入该槽冷却，返回空闲
  -> 失败或取消：不扣能量、不写冷却，返回空闲
```

打开背包、大地图、暂停、物资撤离或结算会关闭 `PlayerInputComponent` 的战斗输入。该状态通过信号立即取消正在进行的瞄准和蓄力；重新启用后必须再次按下技能键，不能沿用旧按键状态。

## 4. 三种索敌协议

### 4.1 指向技能

- 按下后显示技能范围；方向模式绘制以鼠标方向为中心的扇形，位置模式绘制最大释放圆和被距离夹取后的目标位置。
- 鼠标贴近角色产生零方向时沿用上一个有效方向。
- 松开后把 `aim_direction` 与 `target_position` 同时写入执行上下文，行为按自身类型选用。

### 4.2 锁定目标技能

- 按下后显示完整索敌圆。
- 合法目标必须位于技能 `target_group`，通过可选的伤害接口、死亡状态、距离和视线复核。
- 组件在全部合法目标中选择世界位置距离鼠标最近者；鼠标移动会切换当前目标。
- 松开时没有合法目标视为取消，不扣能量也不进入冷却；有目标时同时提供 `target`、目标方向与目标位置。

### 4.3 无索敌技能

- 不显示方向或索敌范围。
- 按下后仍可根据资源配置累计蓄力，松开时不要求方向或目标即可调用行为。

## 5. 蓄力与冷却

- `can_charge=false` 时释放上下文的 `charge_ratio` 固定为 `0`。
- 可蓄力技能从按下开始累计 `charge_seconds`，按 `maximum_charge_duration` 限制，超过上限后保持 `charge_ratio=1` 直到松开。
- 头顶蓄力条只在可蓄力技能按住期间显示；释放、取消、角色切换或战斗输入关闭后立即清空。
- 能量在按下和松开时各预检一次；瞄准或蓄力期间能量被其他动作消耗至不足时，本次松手按取消处理，不执行行为、不扣能量也不进入冷却。
- 每个技能槽独立保存冷却剩余秒数。只有行为 `execute(context)` 明确返回 `true` 才开始冷却和扣除一次能量。
- 冷却由实际经过的非负 `delta` 递减到 `0`，技能栏同步显示一位小数剩余时间。

## 6. 行为接口

主动行为节点可选实现初始化接口：

```gdscript
func configure(caster: Node2D, stats_component: Node, skill_data: Resource, active_skill_component: Node) -> void
```

必须实现：

```gdscript
func execute(context: Dictionary) -> bool
```

上下文固定包含 `caster`、`stats_component`、`skill_data`、`slot_index`、`aim_direction`、`target_position`、`target`、`charge_seconds` 和 `charge_ratio`。行为返回 `true` 表示成功释放；返回 `false` 表示失败且不结算成本。

被动行为节点应实现：

```gdscript
func configure(caster: Node2D, stats_component: Node, skill_data: Resource, passive_skill_component: Node) -> void
func shutdown() -> void
```

`shutdown()` 必须断开外部信号并移除由该技能稳定 ID 写入的属性来源、地图标记或其他长期状态。不同被动不得使用同一个来源 ID。

## 7. 目标与属性协议

- 通用技能目标加入 `skill_targets` 组；开拓！！可计数单位加入 `skill_presence_units` 组。
- 当前怪物通过 `active_skill_target_group` 与 `presence_skill_unit_group` 检查器参数在 `_ready()` 中加入两个组；空组可分别关闭对应资格。宝箱组由星的两个被动资源各自配置为 `loot_chests`，不作为银河全垒打目标，但参与开拓！！计数。
- 距离型击退技能优先读取目标 `get_knockback_decay()`，再用 `v=sqrt(2ad)` 把设计击退距离换算成现有移动组件使用的初始速度；墙体仍会缩短实际位移。
- `CombatStatsComponent.set_skill_stat_multiplier(source_id, attack_ratio, defense_ratio)` 以稳定来源覆盖写入。不同来源按 `∏(1+比例)` 连乘，相同来源重复刷新不会自我叠加。
- 角色属性面板把被动产生的攻防点数独立显示为“技能”值，不并入装备值。

## 8. 星的技能资源

| 技能 | 类型 | 资源 | 行为 |
| --- | --- | --- | --- |
| 开拓！ | 被动 | `res://data/skills/stelle/farthest_chest.tres` | 初始宝箱生成完成后选取距离星最远者，写入独立金色宝箱地图标记；目标移除时清理 |
| 开拓！！ | 被动 | `res://data/skills/stelle/presence.tres` | 每 0.15 秒按相机实际世界视野统计其他单位与宝箱，逐个提高攻防 2%，最高 20% |
| 银河全垒打 | 指向主动、可蓄力 | `res://data/skills/stelle/galactic_grand_slam.tres` | 45° 半角、180 像素方向扇形；15 秒冷却；按资源公式结算伤害和距离型击退 |

星的主动技能只占技能一；技能二、技能三仍显示空技能槽，但 V/B 已完整进入输入绑定系统。穹、银狼当前技能资源数组保持为空，不会错误复用星的技能。

星技能资源还集中保存以下非机制接入参数：开拓！的宝箱组为 `loot_chests`；开拓！！缺少活动相机时使用 `1280×720` 世界像素隔离视野；银河全垒打释放特效持续 `0.24` 秒，使用 `32` 段扇形采样、`0.28` 填充透明度倍率与 `3` 像素轮廓线宽。这些参数默认只在检查器或资源调试时修改，不需要运行时动态写入。

通用视觉默认值：技能栏锚定尺寸 `466×58`、位置 `(-233, -204)`，单槽最小尺寸 `150×58`、槽间距 `8`、冷却显示 `1` 位小数；方向预览采样 `32` 段、轮廓 `2` 像素；蓄力条尺寸 `64×8`、头顶偏移 `(0, -42)`；技能地图标记半径 `7`、最小半径 `3`、轮廓 `2` 像素。上述值只影响显示，不改变命中、冷却、蓄力或地图情报规则。

## 9. 新技能接入

1. 复制相同类型数据资源并填写唯一 `skill_id`、正式名称、说明和全部数值。
2. 创建单一职责行为脚本；通用输入或目标规则应进入技能组件，不要复制到角色行为。
3. 把被动或主动资源加入目标角色的对应数组；一个角色可同时引用多个资源。
4. 新伤害目标显式加入目标组并实现需要的公开接口；不要按节点名或场景路径硬编码识别。
5. 同步角色详情、`docs/游戏机制与玩法内容.md` 中的全部具体数值和本文件的扩展协议。
6. 验证空槽、冷却、能量不足、无合法目标、输入取消、最小与满蓄力、范围边界、遮挡、多目标和角色切换清理。
