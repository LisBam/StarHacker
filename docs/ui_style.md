# 窗口 UI 视觉规范

本文档是项目窗口型 UI 的颜色、尺寸、控件状态和接入方式的唯一维护入口。业务规则与交互流程由机制总表和对应模块文档维护；本文件不拥有玩法数据。

## 核心资源

- `res://scripts/game/ui_style_settings.gd` 是 UI 风格状态与持久化服务，固定保存到 `user://ui_style_settings.cfg`。服务只拥有当前风格标识、主题根登记和即时刷新，不读取玩法、库存、股市、矿场、角色或战斗数据。
- `res://scripts/ui/ui_style_selector.gd` 是主菜单设置与暂停设置共用的单一选择组件，固定显示“UI风格设置”标签，并从 `UiStyleSettings` 读取名称、当前值与保存入口；宿主不得复制风格 ID、中文名称或下拉索引。
- `res://scripts/ui/ui_style_guide.gd` 是无业务依赖的静态样式指南，集中生成 `Theme` 与 `StyleBoxFlat`，只读取 `UiStyleSettings` 的当前视觉标识，不得读取库存、股市、矿场、战斗或其他存档服务。
- `res://scripts/ui/dialog_outer_frame.gd` 是无业务依赖的弹窗最外层框架组件，直接绘制不透明标题栏、青蓝轮廓、标题文字和关闭按钮；组件挂载到 `AcceptDialog` 内部全尺寸面板，不依赖 `Window.embedded_border` 或操作系统窗口透明合成。
- `res://scripts/ui/progress_slider_visual.gd` 是无业务依赖的拖动条视觉组件，通过 `ProgressSliderVisual.install(slider)` 挂载到原生 `HSlider`，只绘制轨道、进度和滑块，不接管范围、步长、输入或业务回调。
- `res://scripts/ui/vertical_split_handle.gd` 是仓库分栏专用拖动条视觉组件；默认跟随当前风格色板（`use_ui_style_palette`），悬停与拖动时中心线切换为强调色并加粗，主题切换通过 `NOTIFICATION_THEME_CHANGED` 即时重绘。
- `res://scripts/ui/combat_hud_slot_view.gd` 是局内紧凑槽位的唯一纯展示组件，统一左侧主动技能槽与右侧武器槽的背景、边框、圆角、居中文字、冷却遮罩和耐久条；组件不读取技能、装备或输入服务，也不发出点击、拖拽或物品操作请求。视图按实例复用背景样式，并在冷却、状态遮罩或禁用值实际变化时才重绘或写入控件。
- `res://scripts/ui/lobby_hud.gd` 是主大厅专用 HUD 宿主，只组合切换按钮、实体交互提示、角色状态与共享紧凑槽位；背包、仓库、商店、锻造、股市、矿场、图鉴和设置继续复用 `MainMenu` 的同一面板实例逻辑。
- `res://scripts/ui/item_card_view.gd` 是库存与商店标准物品卡片视图；它只通过 `UiStyleGuide` 读取卡片背景和边框，品质、耐久、合法目标和业务状态继续由原有语义色控制。
- `apply_screen_theme()` 安装按钮、输入框、下拉框、复选控件、进度条、滑条、滚动条、分隔线、工具提示和弹窗基础主题。
- `apply_window_panel()` 只用于顶层窗口；`apply_section_panel()` 只用于窗口内部装备栏、交易区、统计区和列表区，禁止把全部嵌套面板都提升为主窗口层级。
- `apply_primary_button()` 用于进入、确认、购买、充值、锻造等主要动作；`apply_danger_button()` 用于退出、卖出、清空等高风险动作。普通导航、关闭和返回按钮继续使用默认冷色按钮。
- `apply_title_label()` 统一标题青蓝强调色；业务状态中的收益、亏损、费用和警告仍由对应面板使用语义色覆盖。
- `apply_screen_theme()`、`apply_window_panel()`、`apply_section_panel()`、`apply_screen_background()` 与 `apply_overlay_dim()` 会向 `UiStyleSettings` 登记目标。切换风格后已存在主题、窗口、分区、背景、遮罩和动态子控件必须立即刷新，不要求重进页面或重启游戏。

## UI 风格设置

- 设置页固定提供两项：`black_blue_tech` 显示为“黑蓝科技风”，`black_white_minimal` 显示为“黑白简约风”。首次启动、配置缺失或非法标识均回退“黑蓝科技风”。
- 主菜单设置与战斗暂停设置使用同一个 `UiStyleSelector` 组件；任一入口切换后立即保存并同步另一入口，不使用显示文本或下拉索引作为持久化值。
- “黑蓝科技风”完整保留项目当前深蓝黑表面、青蓝描边、彩色语义状态和业务专属颜色，是默认风格。
- “黑白简约风”只替换通用 UI 的主题色板：页面、窗口、分区、普通按钮、输入框、菜单、滚动条、非语义进度条和滑条使用纯黑、灰色与白灰边框；不使用灰度着色器、全局滤镜或节点材质覆盖。
- 业务语义色和明确局部定义的颜色必须保持原色，包括战斗内武器耐久、生命、能量、护盾、地图图标与标记、股市涨跌、收益/费用/警告、物品品质、技能类型/能耗徽章、红色危险按钮及战斗世界。角色选择页面的生命与能量条属于角色资料预览，随通用色板显示为灰阶；动态创建的通用控件通过其已登记主题根自动继承当前色板，不对其 `Material` 做任何改写。
- 当前风格写入 `user://ui_style_settings.cfg`，属于正式活动存档：随 `.lisbamsave` 导出与导入，并在“删除存档”确认后与其他活动存档一同清空。

## 当前覆盖范围

- 主菜单、主大厅 HUD、主菜单设置、按键绑定、角色选择和战斗内当前角色展示。
- 主菜单设置与暂停设置均在主音量下方显示“UI风格设置”下拉框，选项顺序固定为“黑蓝科技风、黑白简约风”。
- 主菜单设置与暂停设置在“UI风格设置”下方显示“横幅通知”行：左侧 96 像素标签列与其他设置行对齐，右侧为文本“屏幕顶端横幅提醒”的 `CheckButton`（最小高度 38 像素、横向扩展）；两处入口复用同一 `BannerNotificationToggle` 组件并通过服务信号双向同步。
- 局外背包、仓库、商店、锻造、炒股、矿场和开发者菜单。
- 战斗背包、暂停主菜单、暂停设置、训练场设置、角色切换、暂停地图、大地图遮罩、物资撤离和战斗结算。
- 通用确认、存档删除输入确认、数量选择、证券币转账、杠杆开仓和强化结果弹窗。
- 所有弹窗通过 `DialogOuterFrame` 在自身全尺寸面板上直接绘制最外层框架，不再依赖引擎 `embedded_border`。自定义标题栏高度 30 像素，标题背景与青蓝描边透明度固定为 1.0，并使用 2 像素描边、10 像素圆角和 8 像素阴影；内容面板继续保留各自的 0.68 或 0.82 半透明背景，且统一由 `create_dialog_panel_style()` 生成，边框 2 像素、圆角 8 像素，禁止各弹窗自建不一致的边框参数。
- 数量选择与证券币转账弹窗的确认/取消按钮行保留 8 像素底部净空；通用确认与信息弹窗保留 20 像素底部净空，避免按钮与内层或最外层边框相连。
- 商店购买、矿场购买/出售/充值/提现、正式战斗逃跑、开发者清空仓库和普通信息提示等静态文本弹窗统一使用 `CommonConfirmationDialog.present_adaptive()`：窗口宽度按标题、最长正文行和按钮区在 280 至 520 像素之间计算，正文保留 44 像素水平留白，高度由实际换行后的正文与按钮最小尺寸自动计算，禁止业务面板为短文本硬编码大窗口。
- 股市买卖二次确认继续使用固定 480×270 像素窗口，因为正文和可成交状态每 1 秒刷新；固定尺寸用于防止价格变化期间窗口持续缩放和跳位。杠杆平仓确认复用同一固定尺寸窗口与实时刷新协议。
- 杠杆开仓弹窗使用固定 430×292 像素窗口与 0.82 半透明内容面板；做多/做空使用互斥切换按钮行，8 档倍数使用 4 列双行 `GridContainer` 网格（横向间距 8 像素、纵向 4 像素，按钮最小 86×34 像素、文本为纯倍率），两组均为 `toggle_mode` + `ButtonGroup`，按下状态复用主题按压样式；保证金滑条与 82×32 像素数字输入框沿用证券转账弹窗规格。加仓模式复用同一窗口：标题改为“杠杆加仓 · 股票名”，方向与倍数按钮整体禁用只作锁定展示，预览两行分别显示追加费用与“加仓后保证金 · 新均价 · 新强平价”。
- 股市面板标题栏在“关闭”左侧提供 90×36 像素“通知”按钮，底部“全部持仓”标题上方提供 110×30 像素左对齐“历史记录”悬浮按钮——按钮以标题标签手动定位子控件形式向上偏移 36 像素，落在左列股票卡下方的既有空白区，不占用竖向布局行、不改变面板整体尺寸与其余布局；两个入口复用同一 560×420 像素 `StockRecordListDialog` 只读记录窗口——内容为纵向滚动的富文本列表（正文字号 14、行距 6 像素），时间前缀灰色、强平记录红色、普通交易记录白色、通知记录琥珀色，确认按钮文本为“关闭”。
- 全局横幅通知位于 `BannerNotificationService` 的 CanvasLayer 图层 `1200`（高于场景过渡层 `1000`，为全项目最高显示层）：屏幕顶端居中 560 像素宽面板，顶部偏移 12 像素，深色底（透明度 0.92）配 1 像素琥珀描边、6 像素圆角与琥珀色 16 号文字；单条 4 秒（0.25 秒淡入、0.5 秒淡出），面板与文字均不拦截鼠标，且不参与 UI 换肤重建。
- 矿场交易失败与规则提示统一使用通用信息弹窗，不直接创建原生 `AcceptDialog`；单按钮信息与双按钮确认共享同一背景、边框、按钮和居中展示逻辑。
- 主菜单设置页打开时显示与其他局外面板一致的全屏聚焦遮罩；遮罩位于设置窗口下方、其余界面上方，拦截对背后主菜单与底部功能入口的误点，并消除中心按钮透过半透明窗口的残影。
- 矿场与股市面板和其他局外面板共用 `apply_window_panel()` 主窗口样式、25 像素标题与 36 像素高关闭按钮；行情图底板使用当前风格输入框背景色，涨跌折线与事件横幅保持语义色。
- 主菜单与暂停设置的 Master 音量、购买/出售/移动/丢弃/送回/矿场交易数量、证券币充值与提现金额、杠杆保证金滑条统一显示完整范围和当前完成进度。

## 进度拖动条

- 原生 `HSlider` 始终是唯一输入与数值所有者；视觉组件使用忽略鼠标的覆盖层绘制，禁止在视觉组件中连接业务服务或重复实现拖动算法。
- 视觉层每帧比较最小值、最大值与当前值，因此鼠标拖动、键盘调整、业务赋值和 `set_value_no_signal()` 都会刷新已完成进度，不依赖 `value_changed` 信号。
- 轨道按当前控件宽度扣除滑块半径后绘制，最小值和最大值位置均保留边缘空间，避免圆形滑块被自身矩形裁剪。
- 悬停或拖动时进度使用当前 UI 风格的高亮色，滑块半径由 8 像素临时增加到 9 像素；禁用时改用当前风格的低亮度色，但仍保留当前值位置。
- 新增需要显示数值范围的 `HSlider` 时，在控件进入场景树并完成基础属性设置后调用 `ProgressSliderVisual.install(slider)`；重复调用安全返回，不会叠加视觉节点。

## 维护规则

- 新增窗口型 `PanelContainer` 时，根节点先安装统一主题，再应用主窗口样式；内部承载面板默认继承子分区样式。
- 新增完整 UI 根时必须调用 `apply_screen_theme()`；新增完整页面背景与聚焦遮罩分别调用 `apply_screen_background()` 和 `apply_overlay_dim()`，禁止只写死当前黑蓝颜色，否则运行时切换无法刷新该节点的通用主题色板。
- 新增可复用 UI 组件时不得直接依赖 `MainMenu` 或 `CombatHud`；组件应自行安装主题，确保在局外和局内宿主中都能独立显示。
- 新增局内技能或常驻武器槽信息时应扩展 `CombatHudSlotView` 的公开内容与状态接口，不得在 `ActiveSkillBar` 和 `CombatHud` 分别创建重复标签、背景或遮罩；`WeaponSlotControl` 只服务背包等物品交互区域。
- 新增 `AcceptDialog` 或 `ConfirmationDialog` 时必须安装 `DialogOuterFrame`，并为正文预留 `DIALOG_TITLE_HEIGHT` 顶部空间；禁止重新使用 `Window.embedded_border` 充当项目弹窗外框，因为其绘制依赖宿主视口的窗口装饰合成。
- 弹窗宿主必须使用 `CommonConfirmationDialog`、`SellQuantityDialog`、`SecuritiesTransferDialog`、`EnhancementResultDialog` 或 `ItemActionPopup` 的具体类型，并通过 `present...` 前缀公开接口展示；禁止退化为原生窗口类型配合字符串 `call()`，避免接口变更只能在运行时发现。
- 纯文本提示与确认优先复用 `CommonConfirmationDialog`；只有包含数量输入、富文本强化结果或物品操作按钮等专用交互时才新增或复用对应专用弹窗。
- 新增正文不会动态变化的确认入口时优先调用 `present_adaptive()`；只有正文持续刷新、富文本滚动区或业务明确要求稳定尺寸时才调用 `present()` / `present_information()` 并传入固定宽高。
- 新增玩家可操作的 `HSlider` 时必须安装 `ProgressSliderVisual`，确保未完成轨道、已完成进度和滑块位置同时可见。该组件默认跟随 `UiStyleGuide` 色板：黑白简约风的轨道、进度和滑块均为灰阶；只有明确业务语义的局部特例才可关闭 `use_ui_style_palette` 并提供独立颜色。
- 业务脚本只允许覆盖具有明确语义的颜色，例如生命、能量、武器耐久、地图标记、股市涨跌、矿场收益、商店星穹、结算获得与丢失；普通控件交互状态必须留在 `UiStyleGuide`。生命和能量条必须调用 `apply_semantic_progress_bar()`，使主题切换不改写其原有颜色。
- 场景文件不得为通用标题、副标题或说明文字写死 `theme_override_colors/font_color`；局部覆盖优先级高于主题变体，会导致 `apply_title_label` 等接口失效、黑白切换后残留旧色。通用文字颜色一律通过 `apply_title_label`、`apply_muted_accent_label`、`apply_secondary_label` 变体安装。
- 武器槽、锻造槽等物品卡片宿主与 `ItemActionPopup` 的通用背景、边框必须走样式指南取色；作为 `Button` 的宿主须完整覆盖 normal/hover/pressed/disabled/focus 五态，并在 `NOTIFICATION_THEME_CHANGED` 或 `ui_style_changed` 中重建样式，避免风格切换后残留旧色板。
- 危险操作按钮统一调用 `apply_danger_button()` 切换主题变体；业务脚本不得复制独立的红色按钮状态机。
- 物品悬停详情统一使用 `get_tooltip_background_color()` 与 `get_tooltip_border_color()` 取色，与统一主题的 TooltipPanel 保持同一表面，不得在格式化组件内写死颜色。
- 背包、仓库、锻造等动态物品长列表在宿主遮罩隐藏时不得响应库存信号重建卡片；隐藏期间只记录待刷新状态，打开界面时同步一次最新快照。可见状态下同一帧的多个关联信号必须合并为最多 1 次完整列表重建，避免物品数量放大无效 UI 成本。
- 仓库、背包、锻造与图鉴的关键词搜索框统一使用 0.2 秒防抖：输入停顿后才执行全量重建，清空搜索框立即刷新；防抖不吞掉最后一次输入。图鉴目录条目按页签缓存，搜索与解锁刷新不重新加载资源或实例化怪物场景，缓存随内容可用性变化失效。
- 周期刷新的 HUD 组件（槽位冷却文本、耐久条、物品卡片状态）必须带变化守卫：显示值未变化时跳过字符串格式化、控件属性写入与 `queue_redraw()`，避免固定频率刷新放大无效绘制。
- 仓库与共享背包刷新长列表时必须按资源实例复用现有标准物品卡片；普通排序移动只更新拖拽来源下标，跨容器移动只处理实际新增和移出的卡片。未变化卡片必须保留悬停缩放、视觉子节点和信号连接，禁止先清空容器再批量重新实例化。
- 战斗 HUD 附近掉落物列表默认每 0.12 秒刷新，并把同一批查询结果复用于宝箱的“掉落物优先”判断；长按拾取键的首帧执行一次即时全量扫描，长按期间的“掉落物优先”复核仍逐帧执行但基于 0.12 秒批量缓存，宝箱有效性、交互范围与开启进度保持逐帧精确。生存时间、人口和撤离提示默认每 0.1 秒刷新。生命、能量、护盾、装备和库存仍由各自信号即时更新。
- 仓库、共享背包、锻造候选、商店/灰市和物资撤离背包的动态物品长列表统一使用渐进加载：打开或重建时同步显示前 50 张需要新建的卡片，剩余卡片每帧创建 8 张直到完成。加载任务即使在宿主遮罩正式显示前启动也必须继续补齐，避免只保留首批卡片直到下次进入；固定装备槽、标题、筛选和已可复用卡片仍立即显示。筛选、排序、频道、来源或库存再次变化时必须取消旧加载代数，禁止旧批次继续向新页面追加卡片。
- `res://scripts/ui/progressive_item_loader.gd` 是长列表分帧调度的唯一通用组件。组件只保存条目快照、加载代数和创建回调，不读取库存、商店、锻造或物资撤离服务；业务宿主负责卡片配置、信号连接、资源实例复用和过期节点清理。
- 调整任一全局颜色、边框、圆角或按钮状态时必须同步更新本文件；只有变化同时影响操作资格或玩法结果时，才更新《游戏机制与玩法内容》。
- 修改主题后至少运行主菜单、主大厅、角色选择和战斗场景的无窗口启动校验，确保动态创建面板与弹窗都能成功实例化。
- 背包、装备栏、仓库及其展开后的随身物品等长列表必须固定显示垂直滚动条，既支持滚轮也支持直接拖动滑块；嵌套滚动区域需分别验证可见性和拖动范围，不能只验证最外层容器。自动验证必须同时断言滚动条像素厚度大于 0、`max_value > page` 且设置 `value` 后实际数值发生变化。
- 背包与仓库的装备栏使用 18 像素统一间距分隔武器槽和防具槽；开发者窗口禁用横向滚动，并让边距容器与主内容横向填满可用宽度，避免右侧出现无效空白。
- 商店手动刷新按钮直接显示当前星穹消耗，格式固定为“刷新（xx星穹）”；商店与灰市通道标题不附加系统前缀或失败批次说明。

## 12. 护盾与衍生单位展示

- 玩家护盾大于 0 时，生命文本显示“生命 当前/上限  护盾 当前”；护盾归零后移除护盾字段。
- `HealthBar` 上方使用覆盖完整血条的白色滤镜表达当前有护盾，默认透明度 34%；滤镜内部向内缩 1 像素绘制 1 像素宽、92% 不透明度的白色内边框。生命条填充值始终只表示生命比例。
- 具有专属发动条件的主动技能在条件未满足时复用 RGBA `0.16, 0.16, 0.16, 0.72` 禁用滤镜，不显示额外文字；条件满足后移除滤镜。冷却和后续段继续使用各自带秒数遮罩。
- 角色选择与战斗内角色展示在主动技能之后按需显示“衍生单位”，标题字号、颜色、卡片间距、圆角边框与展开交互沿用主动/被动技能规格。
- 衍生单位卡片显示单位名与阵营类型徽章，不显示 CD、能耗；展开后显示攻击类型、可移动状态及全部具体数值。
