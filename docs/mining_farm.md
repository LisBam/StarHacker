# 量子算力矿场

本文档说明量子算力矿场的服务边界、在线结算、资产、联动、UI 和持久化。兑换比例、资产价格、产出、解锁门槛、增益数值与持续时间统一维护在 `docs/游戏机制与玩法内容.md` 第 17、19 章。

## 1. 模块边界

| 实现 | 职责 |
| --- | --- |
| `res://scripts/game/mining_farm_service.gd` | 算力币、资产数量、永久解锁、在线累计、收益、增益与存档的唯一所有者 |
| `res://scripts/ui/mining_farm_panel.gd` | 展示快照、输入数量、播放余额和卡片动效、发起服务命令 |
| `res://scripts/components/mining_income_float_emitter.gd` | 显示真实收益结算产生的飘字，不修改余额 |
| `res://scripts/ui/main_menu.gd` | 创建矿场遮罩并控制面板打开或关闭 |

面板关闭后只停止 UI `_process()`、进度和动画；常驻服务继续按后台周期结算。面板不缓存真实资产所有权，也不直接访问库存或股市内部字段。

## 2. 在线结算

- 服务使用跨场景常驻处理模式，主菜单、局外面板、战斗和暂停都计入在线时间。
- 程序关闭后没有帧回调，因此当前系统不计算离线收益，也不保存退出时间戳。
- 面板打开和关闭使用不同结算频率，但都只消费累计时间中的完整秒数；小数余量保留到下一次结算。
- 单次收益由基础总产出和当前有效增益计算，服务统一向下取整后增加整数算力币。
- 打开面板前先结算后台累计时间，随后由 UI 从上次显示余额过渡到服务真实余额。
- 收益飘字只响应实际产出结算；充值、提现和资产出售不伪装成挂机收益。
- 单个资产卡片的视觉发射按“每台资产每秒一次”累计，每个逻辑次数始终生成一个只显示单台收益的独立飘字。单帧最多创建 12 个标签，超过部分只延后到后续帧逐个展示，不合并数值或字号，也不修改真实余额。

结算周期、取整方式和公式数值见机制总表。

## 3. 资产与解锁

- 资产定义集中在 `MiningFarmService.ASSET_DEFINITIONS`，每项包含稳定 ID、名称、购买价、单台产出、解锁门槛和说明。
- 持有数量是非负整数。购买成功后立即开始参与下一结算周期，出售成功后立即降低基础产出。
- 解锁条件只读取不含临时增益的基础总产出。
- 解锁结果永久保存；达到门槛后，即使出售资产导致基础产出下降，也不会重新锁定。
- 出售价格按当前资产定义计算，不维护历史买入批次或成本。

新增资产必须只在服务定义表中建立一次，并由面板按服务顺序动态展示；不得为单个资产创建专用按钮分支。

## 4. 货币交换

```text
数量弹窗输入整数
    -> 确认弹窗展示兑换结果
    -> MiningFarmService 复核余额与参数
    -> GlobalInventory 原子扣除或增加星穹
    -> 服务增加或扣除算力币
    -> 两个资产服务立即保存
```

- 充值参数表示要扣除的星穹，服务先调用 `GlobalInventory.spend_coins()`，成功后再增加算力币。
- 提现参数表示希望到账的星穹，服务根据兑换损耗反算所需算力币，余额足够后完成两边变更。
- UI 预览不构成最终结果；确认时必须重新校验余额、数量和兑换规则。
- 普通收益与单服务资产交易可合并写入；充值和提现属于跨文件资产变更，必须立即保存。

## 5. 临时增益与联动

### 成功撤离增益

正式骇入成功撤离后，`CombatHud` 把结算前随身物品的实际总价值传给 `apply_successful_extraction_buff()`。训练场、死亡和主动逃跑不调用该接口。多次成功撤离的比例与在线剩余时间按机制规则叠加。

### 股市联动

`StockMarketService` 在行情完成后发送 `market_refreshed(refresh_source)`。矿场只响应 `settlement` 正式刷新，并读取稳定股票 ID `hacker_tech` 的本轮涨跌；面板微行情和局外小幅刷新不改变矿场联动状态。

两类增益在服务内加算后统一作用于基础总产出。UI 只显示服务给出的有效比例和剩余时间。

## 6. UI 约定

- 顶部显示动画余额、星穹折合值、当前每秒产出和增益状态；进度条只表达产出节律，不驱动真实结算。
- 可购买与已持有页使用同一资产顺序。已持有页可保留数量为零的资产占位，但只有真实持有的资产显示运行状态、收益反馈和出售入口。
- 每个资产飘字固定显示单台每秒收益，字号为 12；持有量只提高独立飘字出现频率，不产生合并大飘字。所有资产飘字持续 0.85 秒、上浮 24 像素，横向随机范围为正负 14 像素；单帧创建保护上限为 12。
- 资产解锁门槛只在购买页解释，避免两个页签重复维护同一规则。
- 购买、出售、充值和提现复用 `SellQuantityDialog` 输入整数，随后复用 `CommonConfirmationDialog` 二次确认。
- 交易失败和规则提示使用通用信息弹窗，不直接创建原生 `AcceptDialog`。
- 矿场遵守全局窗口主题；颜色、边框、控件与动效尺寸见 `docs/ui_style.md`。

## 7. 持久化

`user://mining_farm_state.json` 由 `MiningFarmService` 独占，保存：

- 存档版本。
- 算力币余额。
- 各稳定资产 ID 的持有数量。
- 永久解锁表。
- 成功撤离增益比例与剩余在线时间。
- 股市联动状态。

资产定义本身不写入存档。新增资产缺失记录时按零持有处理；删除或改名稳定 ID 前必须提供迁移，否则旧存档资产无法恢复。普通结算与资产交易使用合并保存，跨星穹兑换立即保存矿场和全局库存。

## 8. 扩展约定

- 新收益来源通过服务方法或明确信号接入，不允许 UI 直接修改余额。
- 新增增益时明确其叠加方式、持续时间单位、暂停行为、存档字段和离线规则，并同步机制总表。
- 新增外部联动时使用稳定来源 ID 和枚举式刷新来源，避免依赖显示名称或模糊布尔值。
- 新增资产字段时保持旧存档可缺省读取，并同步资产卡片展示与验证用例。
