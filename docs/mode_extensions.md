# 模式扩展

本文档是模式扩展模块的架构与维护入口。玩家可见规则、全部词条数值与掉落奖励以 `docs/游戏机制与玩法内容.md` 第 29、30 章为权威快照；本文件说明配置流、职责边界、乘算顺序与新增扩展协议。

## 1. 模块组成

| 模块 | 实现 | 职责 |
| --- | --- | --- |
| 规则表 | `scripts/game/mode_extension_rules.gd`（`ModeExtensionRules`） | 声明扩展和风险词条稳定 ID、显示文本、兼容条件、随机候选、配置规范化、局内倍率与掉落奖励 |
| 协议规则表 | `scripts/game/hack_protocol_rules.gd`（`HackProtocolRules`） | 声明 31 项协议稳定 ID、精确数值、碎片成长、三选一、团队平均人口与掉落代价 |
| 选择组件 | `scripts/ui/mode_extension_select_panel.gd`（`ModeExtensionSelectPanel`） | 可复用的多选窗口；展示扩展卡、风险合约四项候选、刷新、必选校验与总奖励 |
| 局内查看组件 | `scripts/ui/risk_contract_view_panel.gd`（`RiskContractViewPanel`） | 只读展示本局已确认风险词条、每项掉落奖励、总奖励与未开启空状态，不允许修改或刷新 |
| 玩家协议组件 | `scripts/components/hack_protocol_component.gd`（`HackProtocolComponent`） | 每名玩家独立维护局内碎片、固定候选、协议层数与运行时效果；不写永久存档 |
| 协议选择/查看 | `scripts/ui/hack_protocol_select_panel.gd`、`scripts/ui/hack_protocol_view_panel.gd` | 不暂停战斗的协议三选一，以及暂停页本机协议只读列表 |
| 单人宿主 | `scripts/ui/main_menu.gd` | 首次正式成功撤离后，骇入模式确认再打开模式扩展窗口；此前清空扩展并直接进入战斗 |
| 联机宿主 | `scripts/ui/multiplayer_lobby_panel.gd` | 把模式扩展作为“多人模式”“骇入模式”之外的第三个规则维度；只有已完成首次正式成功撤离的房主可编辑 |
| 会话状态 | `scripts/game/session_state.gd` | 保存本局扩展 ID 与风险词条 ID；仅运行期有效，不写入永久存档 |
| 联机会话 | `scripts/game/network_session.gd` | 房主权威同步、晚加入补发、房间发现摘要与最终开局指令 |
| 效果协调 | `scripts/game/game_world.gd` | 入场时取得汇总倍率，并分发给怪物、玩家、装备、库存、HUD 与掉落流程 |

UI、会话和战斗组件不得复制风险词条名称或奖励数值。稳定 ID、兼容资格和汇总公式只由 `ModeExtensionRules` 提供。

## 2. 配置流程

### 2.1 单人

1. 玩家在“骇入模式”窗口选择标准、零装或超频骇入；娱乐模式超频骇入在首次正式成功撤离前禁用。
2. 已完成首次正式成功撤离时，主菜单缓存该骇入模式并打开 `780×620` 的“模式扩展”窗口；未完成时标准或零装骇入清空运行期扩展配置并直接开始。
3. 玩家可以勾选多个兼容扩展或完全不选。当前实现包含“风险合约”和“骇入协议”。
4. 启用风险合约时立即随机生成四个候选；玩家至少选择一项才能确认。
5. 点击“刷新词条”免费替换全部四项并清空已选词条，次数不限。
6. 确认后 `SessionState` 同时保存骇入模式、扩展 ID 和词条 ID；返回只回到骇入模式窗口，不提交编辑状态。

每次重新从骇入模式窗口进入扩展选择都从“未开启”开始，不继承上一局风险词条。训练场入口显式清空全部扩展。

### 2.2 联机

完成首次正式成功撤离的房主可在联机面板“模式扩展”行打开同一选择组件，确认后调用 `NetworkSession.set_session_mode_extensions()`；未完成时按钮禁用，服务也拒绝直接调用。超频骇入同样只对已完成首撤的房主可选。配置变化会清空全员准备；客户端只读显示摘要。新成员入册时按“多人模式 → 骇入模式 → 模式扩展”顺序补发当前值。协议版本为 `4`，房间发现回复和最终 `_rpc_begin_combat` 都携带扩展与词条数组；战斗内另可靠互播各成员已获得协议 ID 快照，`enemy_add` 额外携带主机新手保护倍率。

开局 RPC 中的配置是最终权威。每个成员把同一扩展配置写入本地 `SessionState`，再进入战斗；各自的视野、耐久、背包与小地图在本地应用，怪物人口、属性和掉落由主机权威世界应用。

### 2.3 局内查看

战斗暂停主页采用三栏布局：中央暂停菜单、右侧 `420×420` 暂停地图、左侧 `420×420` 模式扩展区域。左栏只显示本局已经启用扩展的 `420×44` 查看入口，未启用的扩展不显示；仅启用一个扩展时按钮垂直居中，同时启用风险合约与骇入协议时两个入口上下排列。点击入口后在同一位置展开对应只读面板，中央菜单和右侧地图保持可见。

`CombatHud` 每次打开时从 `SessionState` 读取当前扩展 ID 和风险词条 ID，确认包含 `risk_contract` 后才显示入口并把词条交给只读组件。组件再次调用 `ModeExtensionRules.normalize_risk_modifier_ids()` 并从规则表读取名称与奖励，不缓存或复制玩法数值。面板显示每项独立怪物掉落加成及加算后的总奖励；未启用合约时入口保持隐藏。

骇入协议面板只读取本机 `HackProtocolComponent`，重复协议聚合为 `×N` 层，不显示队友碎片、候选或协议。ESC 在任一查看面板展开时只关闭该左栏，暂停菜单继续保持；进入宽版暂停设置、训练场设置、角色切换或开发者菜单时入口自动隐藏，避免重叠。查看操作不修改 `SessionState`、不刷新候选，也不影响已经生效的局内倍率。

## 3. 风险候选与合法性

- 每批固定四项。
- 抽取分两步：先在九个效果类别中等概率无放回抽四类，再在每类的强度档位中等概率抽一档。
- 同批不会出现“怪物数量 +25%”和“怪物数量 +50%”这类同效果不同档位。
- 合法配置最多四项、每个效果类别最多一项；未知 ID、重复项、同类多档和超额项会在规则层移除。
- 风险合约没有合法已选词条时视为未启用，不能提交一个空合约。
- 风险合约需要正式物品结算，因此只兼容标准骇入与零装骇入；训练场不提供扩展入口，超频骇入的风险合约控件禁用。

候选随机只决定玩家可以选择的四项，不参与地图共享随机流。联机由房主生成并确认候选，客户端只接收最终稳定 ID。

## 4. 效果结算边界

### 4.1 怪物与人口

- 怪物数量倍率作用于开局人口、全程人口曲线目标和同时运行真实 AI 上限。顺序为“骇入模式倍率 → 风险合约数量倍率 → 联机成员倍率”，每层分别四舍五入。
- 怪物生命、移速和攻击力在出生随机属性波动之后应用。虚拟人口每次实体化到新节点时重新应用一次，随后按虚拟记录保存的生命比例恢复，不会因反复卸载重复叠乘。
- “怪物攻击力”只乘 `attack_power` 属性乘区，不再次放大怪物武器或技能配置的基础伤害字段。

### 4.2 玩家与库存

- 耐久翻倍作用于武器和四件已装备防具。普通武器每次成功使用由 1 点变为 2 点，混合武器由 2 点变为 4 点；玩家实际受伤时每件防具由 1 点变为 2 点。模式级耐久豁免优先于倍率，但风险合约与超频不兼容，因此正常配置不会同时出现。
- 玩家视野倍率与头部装备、套装等视野加成相乘：`最终视野倍率 = (1 + 装备视野加成) × 风险倍率`，相机缩放为 `基础缩放 ÷ 最终视野倍率`。
- 背包基础上限为 50 组，风险倍率四舍五入后分别为 38、25、13 组。入场时已经超过新上限的物品不会被删除或迁移；在降到上限以内前不能新增物品组，但仍可把同签名资源补入已有未满堆叠。结算完成或进入非正式入口后恢复 50 组。
- “禁用小地图”只隐藏右上角局部小地图；Q 键完整大地图、暂停地图、地图探索和导航标记数据继续工作。
- 常规局在 120 秒后生成 3 个正式撤离点；每个点从 36 个环境合法候选中选择与已选点最近距离最大的候选，优先保持两两 4000 像素中心间距。风险词条 `extraction_points_one` 将本局数量覆盖为 1，生成时间、96 像素半径、5 秒驻留和 300 秒地图标记不变。
- 联机在进图当帧用共享种子加 `7717` 的专用随机流预推导全部正式撤离点位置；位置列表不经网络传输，风险合约配置相同的各端会复现同一组 3 点或 1 点布局。

### 4.3 掉落奖励

每项已选词条的奖励先加算：

```text
风险合约掉落倍率 = 1 + Σ(已选词条掉落加成)
怪物单类最终掉落概率 =
clamp(该类基础概率 × 怪物自身掉落倍率 × 风险合约掉落倍率, 0, 1)
```

该倍率只作用于实际击杀怪物时独立判定的武器、装备、强化石和道具四类掉落，不作用于宝箱产出、商店、灰市、物资撤离、悬赏或其他局外奖励。四类判定仍相互独立。

数量词条的奖励低于同档直接战斗压力词条，因为额外人口本身已经增加击杀和掉落来源；高档移速、生命、攻击力、视野和背包限制采用递增奖励，以补偿非线性生存压力。

### 4.4 骇入协议动态代价

- `HackProtocolComponent` 只在正式骇入且扩展 ID 包含 `hack_protocol` 时由 `GameWorld` 动态挂到本地玩家；碎片、候选和效果随场景销毁，不进入 `SessionState` 或永久存档。
- 单机的代价层级等于本机协议总层数；多人先按当前仍在战斗的名册求平均：`团队平均协议数 = 全部有效成员协议层数之和 ÷ 有效成员数`。尚未上报的成员按 `0` 层计入，不能直接使用总和。
- 每个团队平均协议层级使人口目标与实体化上限增加 `12%`，最大增加 `72%`；使怪物四类物品掉落倍率降低 `7%`，最大降低 `35%`。平均层级为 `0` 时两个倍率严格为 `1.0`。
- 人口顺序为“骇入模式倍率 → 风险合约数量倍率 → 骇入协议动态倍率 → 联机成员倍率”，每层分别四舍五入。开局、人口曲线和实体化上限共用该顺序。
- 掉落顺序为“基础概率 × 怪物自身倍率 × 风险合约奖励倍率 × 骇入协议团队代价倍率 × 最终击杀者个人协议倍率”，最后限制到 `0%～100%`。宝箱产出不受团队掉落代价影响。

## 5. 骇入协议运行流程

1. 存活每 `5` 秒获得 `2` 碎片；本机最终击杀获得 `6`；实际取得宝箱出货权获得 `36`。多人只奖励事实归属者。
2. 第一次需求为 `100`，以后每获得一层增加 `75`。碎片可以超过当前需求，选择时只扣除旧需求，余额立即进入下一阶段。
3. 达到需求时组件仅固定随机三项候选并派发提示，不打开界面。候选内部不重复，关闭窗口不刷新；已经获得的协议仍可再次出现并叠加。
4. `CombatHud` 在生命能量面板上方显示碎片条，并从 `InputBindings` 读取当前“选择骇入协议”绑定。持续按住 `3` 秒才打开选择窗口；默认键为 `H`，改键或解绑后提示同步变化。
5. 选择窗口只锁定本机战斗输入，绝不修改 `get_tree().paused`；联机敌人、队友和单机世界继续运行。选择一项后组件整体重建协议效果，不直接修改武器资源或永久角色数据。
6. 联机只可靠广播每名成员已获得协议 ID；碎片、候选与随机结果不传输。主机按最后伤害来源确认击杀归属，并分别结算碎片、回复、技能冷却与个人掉落协议。

首次战斗引导是第 3 至 5 步的明确例外：第一批候选固定为“连发覆写 / 分形散射 / 生命回收”，首次宝箱释放后只补足距离 `100` 碎片门槛尚缺的数量；候选自动打开并暂停单机战斗，选择或关闭后恢复。获得第一项后的后续候选、碎片需求和实时战斗规则全部恢复普通流程。

## 6. 新增模式扩展

1. 在 `ModeExtensionRules.EXTENSION_DEFINITIONS` 增加稳定 ID、显示名、说明和兼容条件。
2. 扩展专属配置继续放在独立规则表中；选择组件只按规则表动态建卡，不把数值写进 UI。
3. `sanitize_configuration()` 必须成为单人、联机、开局和异常网络数据的共同校验入口。
4. 新效果以中性默认值加入 `get_effect_multipliers()`，由最接近数据所有者的组件消费；不要让 `GameWorld` 直接修改无关组件内部字段。
5. 若扩展新增网络字段，更新协议版本、发现回复、晚加入补发、开局最终权威和 `docs/multiplayer.md`。
6. 同步《游戏机制与玩法内容》的精确数值、计算顺序、适用范围与不生效边界。

## 7. 验证清单

- 规则表完整包含需求中的十九项名称、效果与掉落奖励。
- 固定种子多轮抽样始终得到四个不同效果类别；外部传入超过四项或同类多档会被规范化。
- 未启用扩展可直接确认；启用风险合约但未选词条不能确认；刷新清空当前选择。
- 超频骇入不能启用风险合约；训练场清空上局扩展。
- 怪物直接生成与虚拟实体化路径都只应用一次属性倍率。
- 三档背包上限分别为 38、25、13，超上限既有物品不丢失，结算后恢复 50。
- 小地图隐藏但完整大地图仍存在；视野、武器耐久、防具耐久与掉落概率符合公式。
- 常规局达到 120 秒后生成 3 个正式撤离点且两两优先保持 4000 像素间距；`extraction_points_one` 风险词条只生成 1 个，并提供 35% 怪物掉落加成。
- 暂停主页左栏只显示已启用扩展的入口；单入口垂直居中，双入口上下排列且尺寸均为 `420×44`。任一展开后共享 `420×420` 区域，ESC 优先关闭，协议查看只显示本机协议。
- 双实例联机验证房主、客户端、晚加入者和最终开局的扩展数组一致，修改配置后全员准备被清空。
- `tests/hack_protocol_test.tscn` 验证 31 项规则、100→175→250 需求、三选一、250 点碎片选择后保留 150 点溢出、满碎片不自动弹窗、长按 3 秒才打开且场景树不暂停。
- 单人 0 层协议人口与掉落倍率均为 `1.0`；1 层人口为 `1.12`。多人用成员平均层数，成员离场后重新求平均，不能直接相加。
